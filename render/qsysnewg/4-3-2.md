## 4.3.2 Security Levels

| security level as one of the following: | **Level** **10** This is the lowest level of security. When the system security | is set at level 10 and you sign on, the system checks for a user | profile. If it doesn't find one, it simply creates one., | | **Level** **20** At level 20, a user profile must already exist, and the system | verifies that the user ID and password entered match that of the | existing profile., | | **Level** **30** At security level 30, the user ID and password are checked. In | addition, a user can't work with any objects (files or | libraries, for example) without authorization., | **| Lev**e**l** 40 This is the highest level of security. All security-level | considerations for level 30 also apply to level 40. However, | level 40 checks more thoroughly to make sure users only work | with jobs and programs for which they have authority. | Our discussion of user profiles assumes that your system security is set | higher than level 10.
