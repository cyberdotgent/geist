## 1\.1 Advantages of BookServer

Compared to storage of documents as HTML and GIF files in a WWW library, BookServer offers many significant advantages:

For the information provider:

- Much more content \(up to 10 times more\) can be stored on the same amount of server disk space\.
- Each electronic book is a single readily portable and self\-contained file, rather than a large number of separate HTML and GIF files\.
- The same electronic book format can be distributed unchanged across media types \(diskette, CD\-ROM and WWW\) and across operating systems \(OS/2, Windows, AIX, DOS, MVS, VM, OS/400 and CICS\)\.
- The wide variety of supported content input sources for BookManager: many popular word processors, SGML, and BookMaster\.
- Remote access to BookManager libraries from WWW browsers across *every platform*\.
- A single server can serve books, bookshelves and bookcases from its own or from multiple remote file systems\. The actual location is not part of the URL of a document and is transparent to readers\. Therefore the server administrator can move files around, e\.g\., from mainframe to OS/2 or vice\-versa, without affecting how readers access books\. \(Note: Appropriate remote file system support is needed for this, e\.g\. Network File System, Andrew File System or LAN File Services/ESA\. These products are not included with BookServer\.\)
- Support for the rich set of BookManager document elements, including those not directly supported in HTML 2\.0, such as complex tables\.

For the reader, improved function and usability:

- Fuzzy and morphological full\-text searching across entire documents and bookshelves \(not just of the currently loaded HTML file\)
- Easier navigation within documents, via a *automatically generated* button bar with intuitive iconic buttons
