## 2.3.12 Handling External Interrupts

<a id="HDRIUCVS6"></a>

As mentioned earlier, your IUCV program must include an external interrupt handler, as well as setting bit 30 in control register zero to 1 and setting the external interrupt bit in the PSW to 1. (See ["Enabling IUCV"](2-3-6.md) [in topic 2.3.6](2-3-6.md).) This is because IUCV generates external interrupts to pass information to virtual machines. For example, when SOURCE issues the CONNECT function to establish a path with TARGET, IUCV reflects a "pending connection" interrupt to TARGET. When TARGET issues the ACCEPT function to complete the path, IUCV reflects a "connection complete" external interrupt to SOURCE's virtual machine. While the specifics of interrupt handling vary from operating system to operating system, your external interrupt handler should: 1. Gain control when your virtual machine receives an external interrupt. 2. Examine the interrupt. Is it an IUCV-generated interrupt If so, what type of IUCV interrupt is it 3. Respond to the interrupt. If it is an IUCV interrupt, your external interrupt handler must branch to the code that responds to the interrupt. 4. Return control to the program that was in control when the interrupt occurred.
