#### 6.11.4.5 Invoking Multiple Chained Block I/O

Using *BLOCKIO, you can read and write up to 256 contiguous or ?    discontiguous CMS formatted CKD blocks with a single *BLOCKIO request. ?    Individual blocks may be read and written within the same request. ?    Multiple *BLOCKIO requests are specified with a request code in the IUCV ?    SEND parameter list.            Multiple chained block I/O is invoked similarly to single block I/O     requests, but the IUCV SEND parameter list must be set up as follows:          ?   The IPTRGCLS field must be set to F'3', indicating a multiple request.?    ?   The IPRMMSG1 field must contain the number of blocks to process.  Up ?????        to 256 blocks may be specified.???????????????????    ?   The IPRMMSG2 field must contain the guest real address of the ?????????????????        parameter list defining the blocks to be read and written and the ?        buffers to use.         Also returned in the high-order halfword of IPRMMSG2 is the sum of ???????????????        Start Subchannel instructions issued and successful minidisk cache ?        read requests needed to satisfy the multi-block request.

Multiple Block I/O Parameter List: The IPRMMSG2 field of the IUCV SEND parameter list points to a parameter list containing the blocks to be read and written and the buffers to use. Each 16-byte entry contains the information for one block to be read or written. For performance reasons, try not to let the parameter list cross a page boundary. The BPLBK DSECT and BPLBK COPY files are located in the HCPGPI macro library. The contents of this multiple block I/O parameter list are as follows (up to 256 entries):

<a id="FIGUNIQ200"></a>

```text
    _______________________________________________________________ 
   |_______________________________________________________________|
   |_______________________________________________________________|
   |_______________________________________________________________|
   |        .   .   .       .               .               .               .         |
   |        .   .   .       .               .               .               .         |
```

BPLQCOD (M*1) is the 1-byte request code indicating a read or write. X'01' indicates Write, and X'02' indicates Read. BPLSTAT (M*2) is the 1-byte area in which a return code is placed, to indicate the status of the request. BPLBUFAD is a 4-byte field containing the guest real address of the buffer area into which this block should be read or written. Although there are no alignment requirements for the buffer itself, try not to let the buffer cross a page boundary. BPLBKNUM is a 4-byte field containing the number of the block to be read or written. The following conditions are detected before any I/O is initiated. If any errors are detected, no I/O is performed. The return code is stored in the IPRMMSG1 field of the IUCV parameter list as follows: **Return** **Code** **Description** F'0' The multiple block parameter list is set up correctly. F'2' The multiple block parameter list is outside the size of the virtual machine. F'6' An invalid service was requested, for example, IPTRGCLS contains _ a value other than F'1' (Write), F'2' (Read), or F'3' (Multiple). F'7' A storage protection error has occurred on the multiple block parameter list. F'8' The block count specified is not between 1 and 256, inclusive. The following conditions are detected on a per-entry basis and do not prevent other blocks within the same request from being read or written. For those entries in error, no I/O is performed for that block (except where RC = X'05', unrecoverable I/O error). The return code is stored in the status field (MBPSTAT) of the individual entry of the multiple block I/O parameter list that contains the error. **Return** **Code** **Description** X'00' The block has been successfully processed. X'01' The block number specified is invalid. X'02' The buffer is outside the size of the virtual machine. X'03' A write has been requested to a read-only device. X'04' The block size specified is incorrect--format error. X'05' An unrecoverable I/O error has occurred. X'06' The request code is not X'01' for Write or X'02' for Read. X'07' A storage protection error has occurred on the buffer.
