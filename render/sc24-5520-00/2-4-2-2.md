#### 2\.4\.2\.2 CONNECT Optional Input

1\. *A message limit*\. By default, IUCV allows no more than ten outstanding messages for a communications path\. You can change this limit in one of the following ways:

a\. Set a message limit in your virtual machine's VM/ESA user directory entry\. For information on the VM/ESA user directory, see *VM/ESA Installation*\.

b\. Use the MSGLIM=parameter\.

**Note:** If your directory entry **does** specify a message limit, the value used is the smaller of the directory entry or the value specified here\.

Specify the message limit as \(1\) the relocatable label of a halfword containing the message limit, or \(2\) the number of a register that contains the message limit in the low\-order halfword\. 65,535 is the maximum value you can specify\.

c\. Store the message limit in the IPMSGLIM field of the CONNECT parameter list\.

**Note:** If you use the MSGLIM=parameter, IUCV stores this value automatically\.

2\. *Whether you want to receive messages sent to you in your parameter list using the DATA=PRMMSG option*\. To receive messages sent to you in your parameter list using the DATA=PRMMSG option, do one of the following:

a\. Use the PRMDATA=parameter\. PRMDATA=YES indicates that you do want to receive messages using the DATA=PRMMSG option\.

PRMDATA=NO, the default value, indicates that you do not want to receive messages using the DATA=PRMMSG option; you will only accept messages sent using the DATA=BUFFER option\.

b\. Set the IPRMDATA flag \(bit X'80'\) to 1 in the IPFLAGS1 field of the CONNECT parameter list\.

**Note:** If you specify PRMDATA=YES, IUCV sets this flag automatically\.

3\. *The path's ability to handle priority communication*\. To establish a path that can handle priority communication, do one of the following:

a\. Use the PRTY=parameter\. PRTY=YES specifies that a path can handle priority communication\.

**Note:** For your virtual machine to handle priority communication, your user directory entry must include the appropriate statement\.

PRTY=NO, the default value, specifies that a path cannot handle priority communication\.

b\. Set the IPPRTY flag \(bit X'20'\) to 1 in the IPFLAGS1 field of the CONNECT parameter list\.

**Note:** If you specify PRTY=YES, IUCV sets this flag automatically\.

4\. *Whether you want to deactivate, or "quiesce" the path you are establishing*\. To quiesce a path you are establishing, do one of the following:

a\. Use the QUIESCE=parameter\. QUIESCE=YES specifies that IUCV deactivate the path you are establishing\. Messages cannot be sent over a quiescent path\. Use the IUCV RESUME function to reactivate a quiescent path\.

QUIESCE=NO, the default value, specifies that IUCV leave the path active\.

b\. Set the IPQUSCE flag \(bit X'40'\) to 1 in the IPFLAGS1 field of the CONNECT parameter list\.

**Note:** If you specify QUIESCE=YES, IUCV sets this flag automatically\.

5\. *Sixteen\-bytes of data that IUCV reflects to the virtual machine with which you are establishing a path*\. Specify the address of this data area in one of the following ways:

a\. Use the USERDTA=parameter\. Specify the 16\-byte user data area as \(1\) the relocatable label of the 16\-byte user data storage area, or \(2\) the number of a register that contains the address of the 16\-byte user data storage area\.

b\. Store the address of the 16\-byte data area in the IPUSER field of the CONNECT parameter list\.

**Note:** If you use the USERDTA=parameter, IUCV stores this value automatically\.

6\. *MF=L*\. Specify MF=L if you want to build an IUCV parameter list without issuing the IUCV instruction\. This option allows programs to build an IUCV parameter list and pass that parameter list to an operating system that provides an IUCV interface\. The IUCV macro fills in the parameter list in the same manner as if the MF=L option were not specified\. The macro does not initialize any registers, and does not generate the IUCV instruction\.

7\. *If you want the path you are establishing to be a control path*\. Because CONTROL=parameter specifies whether this connection is to be associated with the external interrupt buffer for control paths or application paths, do one of the following:

a\. Use CONTROL=YES to indicate that this path is to be associated with the external interrupt buffer for control paths\.

b\. Use CONTROL=NO to indicate that this path is to be associated with the external interrupt buffer for application paths\.
