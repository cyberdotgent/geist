## 3.7.2.2 APPC/VM States

<a id="HDRSTATESI"></a>

The APPC/VM interface uses a half-duplex communications protocol. This means that only one of the communications partners can send data at any given time. Because of this, APPC/VM uses states to define what functions a program can and cannot issue at any given time. A program is always in a single state for a particular conversation. When your program or your communications partner issues an APPC/VM function, the state of the conversation may change. If your virtual machine is communicating with different virtual machines through various paths, it may be in different states on different paths at the same time. A program participating in multiple conversations could also have multiple states. The basic states for APPC/VM assembler programs are:

Reset The state for each program before communications begin and after communications end. Connect The state for a source program after a connection has been

but before it has completed, or the state for a target program after it has received a connection pending interrupt but before it has accepted. Send The state in which a program is allowed to send data. Receive The state in which a program is ready to receive data. Confirm The state in which a program must respond to its communications partner. Sever The state a program is in when its partner stops communications. These APPC/VM states are based on the states that APPC defines, but there are two differences: 1. The Connect state is unique to APPC/VM 2. The Sever state is analogous to the APPC Deallocate state. In addition, APPC/VM defines several other states for special programs involving coordinated resource recovery (CRR). See topic [3.7.8](3-7-8.md) for details about these APPC/VM states.
