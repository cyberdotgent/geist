## 1\.1\.31 Diagnose Code X'84'\-\-Directory Update\-in\-Place

**Privilege Class:** B

DIAGNOSE code X'84' enables a class B user to replace certain data in any user entry of the CP user object directory\. The user must specify the directory entry and may replace the following data:

- The logon password
- The default virtual machine storage size
- The maximum virtual machine storage size
- Privilege classes
- Logical editing symbols
- The initial program load \(IPL\) system
- IPL parameter data
- The account number
- The distribution code
- User options
- The minidisk access mode
- The minidisk read, write, or multiple password
- The minidisk device type, allocation definition, and volume serial
- Options of the SCREEN directory control statement
- XAUTOLOG user IDs
- The operation mode of virtual machine \(XA\|370\|ESA\)
- The maximum number of virtual processors
- The maximum number of spool files
- User default system resource share option values
- Expanded storage allocation
- Virtual processor ID and VECTOR option values\.

See the individual operation descriptions in [Table 9](<#TBLD84OP>) to understand when the results of each operation take effect\.

DIAGNOSE code X'84' can neither add new entries to, nor delete existing entries from, the object directory\. It can only replace existing object directory data\. Data is replaced in the form created by the DIRECTXA program, that is, in VM/ESA control blocks\. This DIAGNOSE instruction has no effect on definition control statements in the CP user source directory\.

For detailed descriptions of the directory entries, see *VM/ESA CP Planning and Administration*\.

**Entry Values**

Set up the input registers as follows when invoking DIAGNOSE code X'84':

**Rx** Must contain the real address of a variable length parameter list\.

**Ry** Must specify, in bytes, the length of the parameter list\.

The parameter list must contain at least a fixed\-length area 24 bytes long, followed by an optional variable length area of up to 223 bytes and an 4\-byte fence \(X'FF'\) or two sequential blanks\. Data in the fixed\-length area identifies the directory entry to be updated, the password of the user ID associated with the entry, and the data field to be replaced in the directory entry\. All entries in the parameter list must contain unpacked EBCDIC data\. The parameter list is organized as follows:

<a id="FIGFIGUNIQ24"></a>

```
           ___________ 
   x'00'  |  User ID  |
          |___________|
   x'08'  | Password  |       Fixed_length area
          |___________|
   x'10'  | Operation |
          |___________|___________//_____________________ 
   x'18'  |.................    Optional        .........|
          |.............variable_length area..X'FFFFFFFF'|
          |_______________________//_____________________|
```

**Fixed\-length area**

User ID is the user ID of the user whose directory entry is updated\. This is a 1\- to 8\-character, left\-justified value and must be padded with blanks with no imbedded blanks\.

Password is the current CP password of the user ID whose CP directory is updated\. This is a 1\- to 8\-character, left\-justified value and must be padded with blanks with no imbedded blanks\.

If this field is blank, the update\-in\-place function is processed in "testmode\." When the DIAGNOSE is issued in this fashion, the directory is not updated\. Testmode lets you check the syntax of the directory operations without modification of the CP User directory or any operational controls\.

Operation is a 1\- to 8\-character, left\-justified value that identifies the data in the directory entry that is to be replaced\. Valid values and the data that each identifies for replacement are defined in the description of the variable\-length area that follows\.

**Variable\-length area**

is, for each value of the operation field, the data that must be in the variable\-length area of the parameter list, and the format and characteristics of the data\. See [Table 9](<#TBLD84OP>) for specific information concerning all DIAGNOSE code X'84' operations\.

   |                  |     The ten fields are paired into five sets         |

   |                  |     SCREEN.  You must specify these areas in the     |
   |                  |     following order:                                 |
   |                  |                                                      |
   |                  |     1.  CP output                                    |
   |                  |     2.  VM output                                    |

   |                  |     5.  Status area.                                 |
   |                  |                                                      |

   |                  |     field and an extended highlight field (see the   |
   |                  |     SCREEN option description in VM/ESA CP Planning  |
   |                  |     and Administration for valid color and extended  |
   |                  |     highlight values).  Within each doubleword set   |

   |                  |     the extended highlight value.  You must specify  |

**Responses:**

**Exit Values**

Ry Contains 0 unless the condition code is 1, in which case the value is the appropriate return code shown below\.

**Condition Codes:**

Code Meaning

0 The object directory was successfully updated\.

1 DIAGNOSE code X'84' has detected an error\. The directory is unchanged\. The return code defines the error\.

3 DIAGNOSE code X'84' has encountered a paging error while trying to access or update an object directory page\. The directory remains unchanged\. The return code defines the error\.

**Abend Codes:**

Abend Code Meaning

UDU001 An error has been detected in one of the directory blocks for the user\.
