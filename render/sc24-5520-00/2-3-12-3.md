## 2.3.12.3 Responding to IUCV Interrupts

<a id="HDRS3"></a>

#### Responding to IUCV Interrupts After you verify that IUCV caused an external interrupt, you must determine what type of IUCV interrupt it is. To do this, examine the IPTYPE field of your external interrupt buffer. (The address of your external interrupt buffer is contained in the IPBFADR1 field of the DCLBFR parameter list.) If the application declares both a control buffer and a regular buffer, IUCV always reflects the interrupt to the control buffer. The IPTYPE field contains one of the following codes:

**Code** **Interrupt** **Type** 01 Pending connection 02 Connection complete 03 Path has been severed 04 Path has been quiesced 05 Path has been resumed 06 Priority message completion pending 07 Nonpriority message completion pending 08 Priority message pending 09 Nonpriority message pending. For each of these interrupt types, your external interrupt handler should contain or pass control to a routine that responds to the interrupt. To help you find the IPTYPE field and respond to these interrupts, [Chapter 5](2-5.md) describes the following for each interrupt: The cause of the interrupt Some possible responses The format of the external interrupt buffer The meaning of the various fields in the external interrupt buffer.
