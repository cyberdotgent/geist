## 2.5.1 Pending Connection (Type X'01') Interrupts

A pending connection interrupt tells you that another IUCV program has issued the CONNECT function to establish a path with your virtual machine. In response to a pending connection interrupt you can: Complete the path by issuing the ACCEPT function Refuse to complete by issuing the SEVER function.

External Interrupt Buffer Format: The format of the data in the external interrupt buffer is shown in [Figure 17](#FIGPC01I).

<a id="PC01I IPARML DSECT 0 1 2 3 4 5 6 7 0 IPPATHID FLAGS1 IPTYPE IPMSGLIM //////////////// 8 IPVMID 10 IPUSER 18 20 ////////////////////////////////////////////////////////////////// Figure 17. IUCV Pending Connection External Interrupt Format"></a>

IPPATHID contains the path identification number that IUCV assigns the path you are establishing. FLAGS1 contains specific information about the path you are establishing. IUCV treats each bit in FLAGS1 separately. For a pending connection interrupt, IUCV uses the following bits: IPPRTY (X'20') indicates, when set to 1, that the virtual machine that issued the CONNECT function specified that the path can handle priority messages. IPQUSCE (X'40') indicates, when set to 1, that the virtual machine that issued the CONNECT function specified that the path is to be quiescent when established. IPRMDATA (X'80') indicates, when set to 1, that the virtual machine that issued the CONNECT function is prepared to handle message data contained in a parameter list rather than a buffer. IPTYPE contains the interrupt type (X'01'). IPMSGLIM contains the message limit that the virtual machine that issued the CONNECT function specified for this path. IPVMID contains the logon identification (user ID) of the virtual machine that issued the CONNECT. IPUSER contains an optional 16 bytes of data which the virtual machine that established the path can specify.
