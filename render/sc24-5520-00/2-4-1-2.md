#### 2.4.1.2 Optional Input

1.? The path's ability to handle priority communication. To establish a

path that can handle priority communication, do one of the following: a. Use the PRTY=parameter. PRTY=YES specifies that a path can handle priority communication.

**Note:** For your virtual machine to handle priority communication, your user directory entry must include the appropriate IUCV statement. PRTY=NO, the default value, specifies that a path cannot handle priority communications. b. Set the IPPRTY flag (bit X'20') to 1 in the IPFLAGS1 field of the ACCEPT parameter list.

**Note:** Specifying PRTY=YES does this automatically.

2. *Whether* *you* *want* *to* *receive* *message* *data* *in* *your* *parameter* *list* (mes*sage dat*a *sen*t *you* *usi*n*g the* *DAT*A*=PRMMSG opt*i*on). T*o receive (in your parameter list) messages sent to you using the DATA=PRMMSG option, do one of the following: a. Use the PRMDATA=parameter. PRMDATA=YES indicates that you do want to receive messages using the DATA=PRMMSG option. PRMDATA=NO, the default value, indicates that you do not want to receive messages using the DATA=PRMMSG option; you will only accept messages sent using the DATA=BUFFER option. b. Set to 1 the IPRMDATA flag (bit X'80') in the IPFLAGS1 field of the ACCEPT parameter list.

**Note:** Specifying PRMDATA=YES does this automatically.

3. *Whether* *you* *want* *to* *deactivate,* *or* *quiesce* *the* *path* *you* *are* esta*blishing. T*o quiesce a path you are establishing, do one of the following: a. Use the QUIESCE=parameter. QUIESCE=YES specifies that IUCV deactivate the path you are establishing. Messages cannot be sent over a quiescent path. Use the IUCV RESUME function to reactivate a quiescent path. QUIESCE=NO, the default value, specifies that IUCV leave the path active. b. Set the IPQUSCE flag (bit X'40') to 1 in the IPFLAGS1 field of the ACCEPT parameter list.

**Note:** Specifying QUIESCE=YES does this automatically.

4. *A* *message* *limit*. By default, IUCV allows no more than ten outstanding messages for a communications path. You can change this limit in one of the following ways: a. Set a message limit on the OPTION statement in your virtual machine's VM/ESA user directory entry. For information on the VM/ESA user directory, see VM/ESA Installation. b. Use the MSGLIM=parameter. Note that if your directory entry does specify a message limit, the value used is the smaller of the directory entry or the value specified here. Specify the message limit as (1) the relocatable label of a halfword containing the message limit, or (2) the number of a register that contains the message limit in the low-order halfword. 65,535 is the maximum value you can specify. c. Store the message limit in the IPMSGLIM field of the CONNECT parameter list.

**Note:** The MSGLIM=parameter does this automatically.(

5. *Sixteen-bytes* *of* *data* *that* *IUCV* *reflects* *to* *the* *virtual* *machine* *with*

which you are establishing a path. Specify the address of this data

area? in? one of the following ways: a. Use the USERDTA=parameter. Specify the 16-byte user data area as (1) the relocatable label of the 16-byte user data storage area, or (2) the number of a register that contains the address of the 16-byte user data storage area. b. Store the address of the 16-byte data area in the IPUSER field of the ACCEPT parameter list.

**Note:** The USERDTA=parameter does this automatically.

6. *MF=L*. Specify MF=L if you want to build an IUCV parameter list without issuing the IUCV instruction. This option allows programs to build an IUCV parameter list and pass this parameter list to an operating system that provides an IUCV interface. The IUCV macro fills in the parameter list in the same manner as if the MF=L option had not been specified. The macro does not initialize any registers, and does not generate the IUCV instruction.
