## 2.5.4 Message Complete (Types X'06' and X'07') Interrupts

A message complete interrupt tells you one of the following: 1. If the message was a 1-way message, that the user to whom you sent the message has received it 2. If the message was a 2-way message, that the user to whom you sent the message has replied to or rejected. Type X'06' signifies a priority message; type X'07' signifies a nonpriority message.

External Interrupt Buffer Format: The format of the data in the external interrupt buffer is:

<a id="FIGUNIQ90 IPARML DSECT 0 1 2 3 4 5 6 7 0 IPPATHID FLAGS1 IPTYPE IPMSGID 8 :AUD1/:AUD2 ////////////////// IPRMMSG1 10 IPRMMSG2 IPSRCCLS"></a>

18 IPMSGTAG /////////////////////////////// 20 IPBFLN2F /////////////////////////////// Figure 20. IUCV Message Complete External Interrupt Format

IPPATHID contains the path identification number that IUCV associates with the completed message. FLAGS1 contains specific information about the completed message. IUCV treats each bit in FLAGS1 separately. For a message complete interrupt, IUCV uses the following bits: IPPRTY (X'20') indicates, when set to 1, that the completed message was a priority message. When set to 0, IPPRTY indicates that the completed message was a nonpriority message. IPRMDATA (X'80') indicates, when set to 1, that the data associated with the completed message was contained in the parameter list. IPRMDATA indicates, when set to 0, that the data associated with the completed message was contained in a buffer. IPTYPE contains the interrupt type (X'06' for priority messages, X'07' for nonpriority messages). IPMSGID contains the message identification number of the completed message. :AUDIT1/:AUDIT2 contains the audit trail of the message. If no message was found, this field is not modified. The meanings of the bits in the audit trail are: Bit Code Mean**ing** IPADRPLE X'8000' Reply too long for buffer IPADSNPX X'4000' Protection exception on send buffer IPADSNAX X'2000' Addressing exception on send buffer IPADANPX X'1000' Protection exception on answer buffer IPADANAX X'0800' Addressing exception on answer buffer IPADRJCT X'0400' Message rejected IPADPRMD X'0200' Reply data in parameter list not allowed by the originator X'0100' Reserved IPADRCPX X'0080' Protection exception on receive buffer IPADRCAX X'0040' Addressing exception on receive buffer IPADRPPX X'0020' Protection exception on reply buffer IPADRPAX X'0010' Addressing exception on reply buffer IPADSVRD X'0008' Path severed X'0004' Reserved X'0002' Reserved X'0001' Reserved IPRMMSG1/IPRMMSG2 contains message data if the data was sent in the parameter list, rather than a buffer. You can use the label IPRMMSG to refer to the combined contents of IPRMMSG1 and IPRMMSG2. IPSRCCLS contains the message class of the completed message. IPMSGTAG contains the message tag associated with the completed message. IPBFLN2/IPBFLN2F contains one of the following values: If your reply buffer was exactly the correct length, IUCV stores a zero in this field. If your reply buffer was too long, IUCV stores the number of bytes remaining in the buffer (the amount that the buffer exceeded the length of the data) in this field. If your reply buffer was too short, IUCV stores a residual count in this field (that is, the number of bytes remaining in the message that would not fit into the buffer) and sets to 1 the IPADRPLE bit in the audit trail.
