## 1.1.8 Diagnose Code X'04'--Examine Real Storage

PSPI **Privilege** **Class:** C, E Use DIAGNOSE code X'04' to examine first-level CP storage, for diagnostic, monitoring, and tuning purposes only. See the Special Notices statement in topic [NOTICES](notices.md) for a warning on the use of product-sensitive programming interfaces. **Entry** **Values:** Rx Contains the guest real address of a list of CP first-level addresses that you want to examine. Ry Contains the number of entries in the list. Ry+1 Contains the guest real address of the result field. The result field contains the values retrieved from the specified real locations. **Usage** **Notes:** 1. The guest real addresses that you specify in Rx and Ry+1 must be in the same page of guest real storage. Since this DIAGNOSE code is intended mainly for system performance monitoring, it is recommended that this page also be resident in first-level storage at the time the DIAGNOSE instruction is executed. This can be accomplished by having the instruction itself on the same page or by locking the page in first-level storage. Otherwise, DIAGNOSE code X'04' processing causes a page to be paged-in and therefore may affect the performance monitoring data. 2. For a discussion of how VM/ESA processes addresses, refer to ["How](1-1-5.md) Addr [esses Are Processed" in topic 1.1.5. 3.](1-1-5.md) For each address in the list of CP addresses, VM/ESA provides a fullword of data obtained from the specified address in real storage. VM/ESA stores this data into the result field identified by the Ry+1 register. There is a one-to-one correspondence between entries in the list of addresses and entries in the result field. For example, data obtained from the address in the first entry of the address list is stored in the first entry of the result field, data obtained from the second entry of the address list is stored in the second entry of the result field, and this is continued to the last entry. 4. In a multiprocessor environment, each processor has a prefix register that it uses to relocate addresses between 0 and 4095 to another page frame in storage. The prefix register enables each processor to use a different page frame in order to avoid conflict with other processors for such activity as interrupt code recording. Thus, the range 0 through 4095 refers to different areas of storage, depending upon which processor generates the address. All references to first-level storage are handled as if they were made on the IPL processor. 5. Because real storage is volatile, users of this DIAGNOSE code should know that a representation of a storage address may be true for only one given time. 6. The number of entries in the list that you specify in Ry must be greater than zero and cannot exceed 1024, the maximum number of fullwords that can fit on a page; otherwise, a specification exception is returned. 7. An addressing exception occurs if the first-level address that you want to examine is offline, on a directory page, or outside the real machine storage size. **Responses:** None. PSPI end
