## 2\.5\.5 Pending Message \(Types X'08' and X'09'\) Interrupts

A pending message interrupt tells you that another IUCV program has sent you a message\. Type X'08' signifies a priority message; type X'09' signifies a nonpriority message\.

How you respond to pending message interrupts depends on the types of messages you are using IUCV to send\.

*External Interrupt Buffer Format*: The format of the data in the external interrupt buffer is:

<a id="FIGFIGUNIQ91"></a>

```
      IPARML DSECT

      0      1        2         3         4         5         6       7
      ______________ _________ _________ _________________________________ 
    0|   IPPATHID   | FLAGS1  |IPTYPE   |             IPMSGID             |
     |______________|_________|_________|_________________________________|
    8|           IPTRGCLS               |             IPRMMSG1            |
     |______________ ___________________|_________________________________|
   10|   IPBFLN1F   |IPRMMSG2           |//////////////////////////////// |
     |______________|___________________|_________________________________|
   18| ////////////////////////////////////////////////////////////////// |
     |__________________________________ _________________________________|
   20|           IPBFLN2F               |  ////////////////////////////// |
     |__________________________________|_________________________________|
```

*Figure 21\. IUCV Incoming Message External Interrupt Format*

`IPPATHID` contains the path identification number that IUCV associates with the pending message\.

`FLAGS1` contains specific information about the pending message\. IUCV treats each bit in FLAGS1 separately\. For a pending message interrupt, IUCV uses the following bits:

`IPNORPY (X'10')` indicates, when set to 1, that the message is a 1\-way message and does not take a reply\. IPNORPY indicates, when set to 0, that the message is a 2\-way message and does take a reply\.

`IPRMDATA (X'80')` indicates, when set to 1, that the data associated with the message is contained in the fields IPRMMSG1 and IPRMMSG2\. IPRMDATA indicates, when set to 0, that the data associated with the message is contained in a buffer\.

`IPTYPE` contains the interrupt type \(X'08' for priority messages, X'09' for nonpriority messages\)\.

`IPMSGID` contains the message identification number that IUCV associates with the pending message\.

`IPTRGCLS` contains the message class of the pending message\.

`IPRMMSG1/IPRMMSG2` contains the message data if the data was sent in the parameter list, rather than a buffer\. You can use the label IPRMMSG to refer to the combined contents of IPRMMSG1 and IPRMMSG2\.

`IPBFLN1/IPBFLN1F` contains the length of the pending message\.

`IPBFLN2/IPBFLN2F` contains the length of the reply or reply area\.
