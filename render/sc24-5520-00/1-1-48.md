## 1.1.48 Diagnose Code X'DC'--Declare/Delete Virtual Buffer for Application Data

**Privilege** **Class:** Any Use DIAGNOSE code X'DC' to notify CP that the specified buffer is declared

or deleted for CP monitoring. Once the buffer has been declared for monitoring, all data in it is recorded by CP at each sample interval when application data monitoring is enabled by the MONITOR ENABLE APPLDATA command. In other words, CP generates monitor records containing all the data as found in the buffer at the time of the interval. For more information on the command, refer to VM/ESA CP Command and Utility Reference. An application may place data into the buffer at any time. CP monitor records containing the application data may then be used for performance analysis.

**Note:** VM/ESA monitor records produced by CP are product-sensitive

programming interfaces. Refer to [Appendix B, "Monitor Records" in](b-0.md) [topic B.0](b-0.md) for more information about monitor records.

**Entry** **Values:** In order to issue DIAGNOSE X'DC', the user's directory must contain an

OPTION APPLMON statement. Rx Specifies the guest real address of the parameter list. Ry Used for responses, no entry value required Rx and Ry may be the same register. The parameter list format is as follows: 0 DIAG FCN LEN PRODUCT ID ADDRESS 8 //// BUFFER LEN BUFFER ADDRESS DIAG is a 2-byte field containing the DIAGNOSE code X'DC'. FCN is a 1-byte field specifying the function code of the DIAGNOSE: X'00**'** START INTERVAL RECORDING Declare the buffer for CP monitoring. Application data is collected from this buffer by CP at each sample interval. The application may declare more than one buffer from the same virtual machine. X'01**'** STOP INTERVAL RECORDING Delete the buffer from CP monitoring. Application data is no longer collected from this buffer because CP does not check for overlapping or whether the same buffers are being declared. If the APPLDATA domain is enabled for event monitoring, CP generates an event monitor record indicating that collection of application data has stopped. LEN is a 1-byte field specifying the byte length of the parameter list. The minimum length is X'10'. A length beyond X'10' is allowed, but only the first 16 bytes are used by CP. PRODUCT ID-ADDRESS is a 4-byte guest real address of a 16-byte field that identifies the product that is generating the data. A suggested format for the PRODUCT-ID-ADDRESS is pppp*pppffnvvrrmm,* where pppp*ppp is* the product number or unique name, ff i*s* the function of the product, n is the record number of the product, vv i*s* the version, rr i*s* the release, and mm i*s* the modification level. CP does not check or interpret this data; it is included in all monitor records generated for this buffer. This data may be useful for identification purposes.

**Note:** This field is not specified with function code X'01'.

//// is a 2-byte reserved field. BUFFER-LEN is a 2-byte field specifying the length of the application data buffer. The minimum value for BUFFER-LEN is 1; the maximum value is 4024.

**Note:** The maximum figure is derived to provide minimal space in a 4KB page for the static portion (APLSDT_APHDR) of the monitor record, MRAPLSDT, and the end-of-frame monitor record, MRMTREOF.

See Appe [ndix B, "Monitor Records" in topic B.0 for](b-0.md) information on how to access and print the layouts or lengths of the monitor records. BUFFER-ADDRESS is the 4-byte guest real address of the application data buffer.

**Exit** **Values:**

Ry contains the return code and the condition code as set. See the "Responses" section for descriptions. **Usage** **Notes:** 1. When a DIAGNOSE X'DC' STOP is issued against one of the multiply-defined buffers, monitoring stops for all the buffers. 2. Recording of application data takes effect only when the application has issued DIAGNOSE X'DC' to declare the buffer and its user has been enabled (via the CP MONITOR command) for monitoring in the APPLDATA domain. 3. If a buffer, or any part of it, resides within a saved segment outside the virtual machine's storage, and this segment is then purged, CP executes a DIAGNOSE X'DC' STOP on this buffer, thereby stopping application data collection from this buffer. **Responses:** Upon completion of DIAGNOSE code X'DC', the following return codes will be placed in Ry:
