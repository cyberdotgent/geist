#### 6.11.14.1.1 IUCV CONNECT to the *SPL System Service

IUCV CONNECT to *SPL for Printer Service: An IUCV CONNECT is issued by the virtual machine with USERID=*SPL, PRIORITY=NO, PRMDATA=YES, and USERDTA=*prtid* name. A *prtid* name is a 1- to 8-character alphameric name your installation assigns. If you specify a *prtid* name of four or fewer characters, the name **cannot** contain all hexadecimal characters. For example, FFFF is **not** a valid *prtid* name, whereas FFFFF is. BLD is another example of a valid name. A *prtid* name cannot be ALL. A *prtid* name must **not** contain imbedded blanks; however, trailing blanks are permitted. It is the installation's responsibility to control the names assigned to *prtids*. The name should not conflict with any other names, options, or notation the installation uses. Example: It is recommended that a *prtid* name should not: Be the same as a user ID on the system Be "PROC" or "PROCESSOR" Include a dash (-) Be a name that could be confused with a logical device number, for example, L1234. The *SPL system service allows multiple virtual machines to be connected with the same *prtid* name. This way, when you use the *SPL system service SEND function, each virtual machine of the specified *prtid* name is sent a message. If you want to create your own IUCV parameter list, the IPUSER user data field must have the following data: `ORG` `IPUSER` `SPLNAME` `DC` `CL8` `PRTID` IUCV CONNECT to *SPL for Reader Service: An IUCV CONNECT is issued by the virtual machine with USERID=*SPL, PRIORITY=NO, PRMDATA=YES, and USERDTA=IPUSER(1:9). The IPUSER field from bytes 1 to 9 contains the following information: `RDRID` `DS` `CL8` `Set` `to` `blanks` `The` `bits` `defined` `in` `IPRFLAG1` `are:`

`IPRDR` `EQU` `X'80'` `Connection` `for` `the` `reader` `notify` `function` If all the parameters required by *SPL system service are valid, the *SPL

system service issues an IUCV ACCEPT to complete the connection with the virtual machine. All other *SPL system service functions depend on the IUCV CONNECT and ACCEPT being complete. Reasons the CONNECT Function May Sever: If any of the parameters passed to *SPL system service are invalid, *SPL system service issues an IUCV SEVER. When the *prtid* is ready to end its connection with *SPL system service, the *prtid* then issues an IUCV SEVER. Any spool files being processed at the time of the SEVER remain unchanged. The following situations are considered user errors and cause the *SPL system service to sever the IUCV path to the *prtid*: A CONNECT issued was with QUIESCE, return code X'80' A CONNECT issued was with PRIORITY, return code X'80' A CONNECT issued was with PRMDATA=NO, return code X'80' A CONNECT issued was with a prti*d nam*e, that is: ALL Contains imbedded blanks Is four or less hexadecimal digits. When the *SPL system service CONNECT issues a SEVER, the format of the IPUSER field is: IPUSER+0: 1-byte error code of X'80' IPUSER+1: 1-byte reserved field of X'00' IPUSER+2: two bytes, containing IPMSGID from the IUCV parameter list that caused the error. When the reader service issues a CONNECT, and the *SPL system service has 8 (maximum) connections with reader service machines, *SPL issues a SEVER. The format of the IPUSER field is: IPUSER+0: 1-byte error code of X'80'. The following situations are considered user errors and cause the *SPL system service to sever the IUCV path to the reader service machine: A CONNECT issued was with QUIESCE, return code X'80' A CONNECT issued was with PRIORITY, return code X'80' A CONNECT issued was with PRMDATA=NO, return code X'80'. When the *SPL system service CONNECT issues a SEVER, the format of the IPUSER field is: IPUSER+0: 1-byte error code of X'80'
