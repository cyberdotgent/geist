## 1.1.37 Diagnose Code X'A4'--Synchronous Input/Output Operations (For DASD in Standard CMS Blocksize)

**Privilege** **Class:** Any Use DIAGNOSE X'A4' to perform synchronous input/output operations to a direct access device formatted by CMS and supported by VM/ESA. DIAGNOSE X'A4' operates in XA, 370, or ESA mode. Results of the I/O operation are contained in the synchronous block I/O parameter list (HCPSBIOP) and in the condition code and return code. **Entry** **Values:** Rx Contains the real address of the synchronous block I/O parameter list (HCPSBIOP). Ry Not used Two different I/O operations can be performed through DIAGNOSE X'A4': Read and Write. Operations are specified using the request-type field of the HCPSBIOP. The way to request each operation is described below. Synchronous Block I/O Parameter Block (HCPSBIOP): The synchronous block I/O parameter block (HCPSBIOP) is the parameter list that DIAGNOSE X'A4' uses in controlling the block I/O request. These parameters include: The virtual device number The storage protection key The request type The block size The address of the block number/data address list The number of pairs in the block number/data address list The number of blocks processed by CP The device and subchannel status The residual count The sense data count The sense data. The two rightmost bits of the HCPSBIOP address must be zeros, placing the HCPSBIOP on a word boundary; otherwise a program-check/specification exception is recognized. HCPSBIOP has the following format (the HCPSBIOP COPY file is provided in the HCPGPI macro library): SBIOP DSECT Word Dec 0 Device # Stor I/O Block size age re pro quest tec type tion key 2 Address of block entries Count of block entries 4 Blocks processed by CP Device Sub Residual status chan count nel status 6 0000000000000000000000000 Logi 000000 Sense count cal path mask 8 000000000000000000000000000 000000000000000000000000000 10 000000000000000000000000000 000000000000000000000000000 12 000000000000000000000000000 000000000000000000000000000 14 Sense Data = 21 The fields in the HCPSBIOP are defined as follows: Device #: Bits 0 through 15 of word 0 contain a virtual device number (1 to 4 digits) of the DASD to which this operation is targeted. The DASD must be fully supported. This field is filled in by the issuer of the DIAGNOSE, and is returned unchanged. Four-digit device numbers are allowed in both 370-mode and ESA-mode virtual machines. Storage Protection Key: Bits 16 through 19 of word 0 contain the subchannel key for all fetching of output data and for the storing of input data associated with the start function. This key is matched with a storage key during these storage references. Bits 20 through 23 must be zeros; otherwise a program check/operand exception condition is recognized. Bit 20 represents suspend control which is not supported. The storage protection key is filled in by the issuer of the diagnose and is returned unchanged. I/O Request Type: Bits 28 through 31 of word 0 contain the request type for this I/O operation. If bit 30 of word 0 is 1, then the I/O operation is to read data from DASD to storage. If bit 31 of word 0 is 1, then the I/O operation is to write data from storage to DASD. The user must set only one of the 28 through 31 bits--the others must be zeros; otherwise, a program check/operation exception condition is recognized. Bits 24 through 27 of word 0 are reserved for future use and must be zeros; otherwise, a program check/operation exception condition is recognized. The I/O request-type bits are as follows: Wr`ite =` `B`'`0000 0`0`01'` Re`ad` = `B`'`0000 0`0`10'` Anything else is invalid. Block Size: Bits 0 through 31 of word 1 contain the size of the storage blocks for this request. The blocksize must be one of the following: 0512 1024 2048 4096 If you set the blocksize to other than the above, processing of the DIAGNOSE terminates and a return code of 8 and a condition code of 2 are set. For a Read or Write request, if the blocksize does not match the physical blocksize of the (CKD) DASD, the DIAGNOSE request ends with an incorrect length indication. *Programming* *Note:* The first DIAGNOSE X'A4' issued to a device should attempt to read the volume label with a 4KB (4096) blocksize to verify that the volume has been properly formatted for CMS use. The incorrect length indication, the residual count, and the data transferred may then be used to verify the actual blocksize. Address of Block Entries: Bits 0 through 31 of word 2 designate the location in guest absolute storage of the list of DASD block number and data address pairs for this request. This list is described in the SBILIST. The three rightmost bits of the block entries address must be zeros, specifying that the SBILIST is on a doubleword boundary; otherwise a program check/operand exception condition is recognized. If the data address specifies a location protected against fetching or specifies a location outside the storage of the virtual machine, the processing of the DIAGNOSE terminates and a return code of 10 and a condition code of 2 are set. Count of Block Entries: Bits 0 through 31 of word 3 contain the count of DASD block number and data address pairs in the SBILIST. For a read or write request, the maximum allowed is 500, and the minimum is 1; otherwise, the processing of the DIAGNOSE terminates, and a return code of 11 and a condition code of 2 are set. This is an unsigned binary number. The field is returned unchanged. Blocks Processed by CP: Bits 0 through 31 of word 4 contain the number of blocks that were successfully processed by the Control Program. Blocks are processed sequentially, in the order the user provided. The data areas associated with unprocessed blocks are unpredictable. Device Status: Bits 0 through 7 of word 5 identify the conditions in the device when the channel program ended. Each of the eight bits represents one condition, as defined in IBM Enterprise Systems Architecture/370 Principles of Operation. This is returned to the issuer. Subchannel Status: Bits 8 through 15 of word 5 identify the conditions in the subchannel when the channel program ended. Each of the eight bits represents one condition, as defined in IBM Enterprise Systems Architecture/370 Principles of Operation. This is returned to the issuer. Residual Count: Bits 16 through 31 of word 5 contain the residual count from the CCW in control when the channel program ended. This is returned to the issuer of the diagnose. Reserved: Bits 0 through 31 of word 6 are reserved for future use and must be zeros; otherwise, a program check/operand exception condition is recognized. Logical Path Mask: Bits 0 through 7 of word 7 contain a mask of paths that the channel subsystem can use to execute the I/O operation requested by the DIAGNOSE. If the issuer of the DIAGNOSE requires that the I/O be issued down a specific path, that path must be represented in this field. If this field contains zeros, the issuer of the DIAGNOSE does not wish the I/O operation to be restricted to a particular path or paths.

**Note:** A positional correspondence exists between the bit positions in the logical path mask and the channel path IDs in the subchannel.

Reserved: Bits 8 through 15 of word 7 are reserved for future use and must be zeros; otherwise, a program check/operand exception condition is recognized. Reserved: Bits 0 through 15 of word 7 are reserved for future use and must be zeros; otherwise, a program check/operand exception condition is recognized. Sense Data Count: Bits 16 through 31 of word 7 contain the amount of sense data present if a unit check is indicated. This is returned to the issuer of the DIAGNOSE. This field is returned unchanged if unit check is not present. Reserved: Bits 0 through 31 of words 8 through 13 are reserved for future use and must be zeros; otherwise, a program check/operand exception condition is recognized. Sense Data: Bits 0 through 31 of words 14 through 21 contain the sense data (as limited by the sense data count) if a unit check is indicated. This is returned to the issuer of the DIAGNOSE. This field is returned unchanged if unit check is not present. The block entries (SBILIST) describing the DASD block number and data address pairs have the following format: 0 Block number Data address The fields in the SBILIST are defined as follows: Block Number: Bits 0 through 31 of word 0 contain the DASD block number for this request. This is provided by the issuer of the DIAGNOSE. Block numbers are assigned sequentially to DASD records, starting with zero. Data Address: Bits 0 through 31 of word 1 designate the location of the data for this request in guest absolute storage. For a Write request, this is the location in storage from which the data is written to DASD. For a Read request, this is the location in storage to which the data read from DASD is placed. If the data address specifies a location in a shared segment for a read request or specifies a location outside the storage of the virtual machine, the processing of the DIAGNOSE is terminated and return code 12, condition code 2 is set. The field in HCPSBIOP called "blocks processed by CP" indicates the number of list entries for which data transfer was successful. List entries are processed sequentially, in the order the user provided. The "blocks processed by CP" field is set to zero if the error was detected before any I/O was attempted. Read or Write Operation: The following fields of the HCPSBIOP block must be filled in: The virtual device number The storage protection key The request type, block size, The address of the block number/data address list The number of pairs in the number/data address list. The area referenced by the number/data address block list must contain the DASD block number and data address in absolute storage for each Read or Write operation. For a Write operation, this data address is the location in storage from which the data is written to DASD. For a Read operation, this data address is the location in storage where the data read from storage is placed. See the "Responses" section for the HCPSBIOP fields that are filled in upon completion of the operation. **Usage** **Notes:** 1. No I/O interrupts are returned by CP to the virtual machine; the DIAGNOSE instruction is completed only when the Read or Write commands associated with the DIAGNOSE are completed. 2. On 3340 devices, blocks 0 and 2 (records 1 and 3) may not be the actual size indicated by the blocksize from the parameter list when read. The channel program built by DIAGNOSE code X'A4' automatically takes care of the possibly different blocksize on this device; the user should code the blocksize of the data records (for example, 512, 1024). The first record (block number 0) has a physical size of 80 (the architected size of the IPL record), and the third record (block number 2) has a physical size of 80 (the IBM standard for a volume label). 3. One way to figure out the blocksize automatically is to read block 2 (record 3, the label record) and look at the length field. The length field is in the fourth word of the record. 4. In a System/370 virtual machine, I/O cannot be specified for a device with a number greater than X'1FFF'. **Responses:** Upon completion of a Read or Write operation, HCPSBIOP is updated with the number of blocks processed by CP, the device and subchannel status, the residual count, the sense data count and the sense data (if a unit check is indicated). Upon completion of DIAGNOSE X'A4', you receive a condition code, along with a return code in register 15: If you receive a condition code of 0, the I/O operation completed successfully. The return code in register 15 is 0 also. If you receive a condition code of 1, an error condition was detected which prevented complete execution of the channel program built for the DIAGNOSE I/O request.
