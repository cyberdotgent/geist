Record caching does not stage in the rest of track after a block has been read into cache and so is very attractive for the random I/Os characteristic of online transaction processing. DASD Fast Write will still be achieved (in fact is guaranteed with record caching) and dynamic cache management will switch to track caching should it become appropriate, as for sequential BMPs. DCME has supported VSAM database data sets since it became available. IMS 5.1 provides the same benefits to users of OSAM. So the OSAM DCME support has the potential to improve the efficiency of cache usage, which will enable better overall I/O subsystem performance. Those customers who have been forced to turn caching off for OSAM databases will, with IMS 5.1, be able to use caching and gain the benefits of DASD Fast Write, and perhaps the occasional fast read. Sequential BMPs and batch jobs will automatically utilize track caching, and so they too will benefit significantly.
