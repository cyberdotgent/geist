## 8.2 Running IPCS Subcommands in Batch Mode

<a id="HDRBATSB"></a>

[Figure 8-2](8-2.md) is an example of running the RSMDATA subcommand in a batch job. Note the following in this example: The batch job allocates the dump directory, IPCSU1.DUMP.DIR, assuming an existing dump directory data set. The IPCS session parameters are dynamically allocated from SYS1.PARMLIB. The RSMDATA subcommand is accessed from the BLSCECT member. The output is directed to the IPCS print data set, IPCSU1.RSMDATA.LISTV, and can be viewed using PDF BROWSE. | The dump data set is allocated to the file DUMP. DUMP is an arbitrary | DD name; however, the dump directory associates that file name to the | dump 'IPCSU1.DUMP1.DUMP' when it is first initialized. c.cp 12 The SYSTSIN in-stream data contains two DROPDUMP subcommands. The first DROPDUMP subcommand ensures that the dump directory being used does not contain any information about another dump data set that was identified to IPCS through the same file name, FILE(DUMP). If another dump data set had been processed through FILE(DUMP) using the same dump directory and this DROPDUMP subcommand were not included, IPCS would detect the attempt to associate the descriptions of two distinct dumps with FILE(DUMP) and would end the processing of the RSMDATA subcommand. The second DROPDUMP subcommand removes the description of the dump processed, assuming that the next time the same dump directory is used, another dump will be of interest. This is not essential if the next job begins with a DROPDUMP operation similar to the one at the start of the job, but it does eliminate records that will not be reused in subsequent IPCS sessions.
