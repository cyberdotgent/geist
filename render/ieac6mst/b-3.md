The IPCS procedure in [Figure B-3](b-3.md) and the PRSVCDMP CLIST in [Figure B-6](b-3.md) work together to provide the function of printing, copying and clearing a dump data set. You should use the following steps in tailoring similar procedures and CLISTs to perform their normal dump processing tasks. 1. Create a procedure in SYS1.PROCLIB. IPCS provides a procedure called BLSJIPCS which has an alias of IPCS in SYS1.PROCLIB. This provides the base for the tailored procedure. You should name the procedure something other than IPCS to avoid conflict with the one provided with MVS. Tailor the procedure to look like the one in Fig [ure B-3.](b-3.md) 2. Tailor the OUTFILE DD statement to reflect where you want the SVC dumps to be copied. This can be modified to define a tape for receiving dumps. 3. Tailor the defaults for the procedure to save operator keystrokes. For example, if the SYS1.DUMPxx data sets are always to be cleared, */ change the "CLEAR=NOCLEAR" to "CLEAR=CLEAR". The OUTDUMP keyword can be eliminated if the OUTFILE DD statement always goes to a non-label (NL) t`ape. The DUMP keyword could be modified to require the opera`tor to specify only the last 2 digits of the dump data set name. The ideal setup would be a procedure which can be invoked as S IPCS,DUMP=01 to process a dump in SYS1.DUMP01. 4. For the formatted output, change the SYSOUT=A to the desired print class. 5. When this procedure is run as a START command, it will use or create a dump directory called SYS1.DDIR. Before using this dump directory, the CLIST will always clear out any information saved for the previous dump of the same name. This prevents the SYS1.DDIR dump directory from running out of space. c.cp 999 6. The SYSPROC DD statement identifies the library or libraries where CLISTs are located.
