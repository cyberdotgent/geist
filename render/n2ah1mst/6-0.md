# 6\.0 AMD Messages

<a id="MSG"></a>

<a id="MSG AMD001A"></a>

- **AMD001A** **ENTER** **ADDRESS** **OF** **OUTPUT** **TAPE** — **Explanation:** The stand\-alone dump program requires the device number of the dump output device\. **Source:** Stand\-alone dump \(SADMP\) **System** **Action:** The stand\-alone program waits for a response\. **Operator** **Response:** Prepare a tape that is not already assigned to another system, ready the device, and reply to stand\-alone dump by entering the 3\-character device number\. If the default device number is to be used, give a null reply\. Be sure to insert a file protect ring or to disable file protection\.

<a id="MSG AMD003I"></a>

- **AMD003I** **I/O** **ERROR** **ON** **dev** **STATUS=ccccccccddssllllsens** — **Explanation:** During processing of the stand\-alone dump, an I/O error that could not be corrected occurred\. In the message text: dev The device address\. cccccccc The channel program address\. dd The device status\. ss The subchannel status\. llll The residual length\. sens The sense data, if available\. **Source:** Stand\-alone dump \(SADMP\) **System** **Action:** If the error occurs during initialization, stand\-alone dump reissues message AMD001A\. Otherwise, the stand\-alone dump program ends, and the system enters a wait state\. **Operator** **Response:** If all of the following are present, an output tape that was not initialized may have caused the failure: 1\. This message indicates an interface control check for the output tape device\. 2\. The stand\-alone dump program did not issue message AMD005I\. 3\. The installation specified TIMEOUT=YES in the Input/Output Configuration Program \(IOCP\) generation on an IODEVICE macro\. If message AMD005I has not been issued and tape caused the I/O error, mount a new tape that has been initialized with a tape mark on a different drive, if possible\. Rerun the dump program by doing a system restart\. If a printer is failing, rerun the stand\-alone dump program by doing a system restart, then selecting an alternate printer\. **Note:** If the stand\-alone dump program is loaded a second time, certain locations will not reflect the original contents of central storage\. Therefore, if message AMD005I is absent, use system restart to rerun the stand\-alone dump program\.

<a id="MSG AMD004A"></a>

- **AMD004A** **END** **OF** **REEL\.** **MOUNT** **AN** **ADDITIONAL** **OUTPUT** **TAPE\.** — **Explanation:** While writing to tape, the stand\-alone dump program detected an end\-of\-volume condition\. **Source:** Stand\-alone dump \(SADMP\) **System** **Action:** The stand\-alone dump program marks and unloads the tape volume\. The dump program stops processing until the operator mounts a tape volume\. **Operator** **Response:** Mount another tape volume\.

<a id="MSG AMD005I"></a>

- **AMD005I** **DUMPING** **OF** **REAL** **STORAGE** **NOW** \{IN PROGRESS\|COMPLETED\}\. — **Explanation:** In the message text: IN PROGRESS The stand\-alone dump \(SADMP\) program has started the dumping of central storage\. COMPLETED The SADMP program has successfully dumped central storage\. **Source:** Stand\-alone dump \(SADMP\) **System** **Action:** The SADMP program continues\.

<a id="MSG AMD008A"></a>

- **AMD008A** **ENTER** **ADDRESS** **RANGE\.** **'R,NNNNNNNN:MMMMMMMM'** — **Explanation:** The printable stand\-alone dump program is requesting a dump of an address range\. **Source:** Stand\-alone dump \(SADMP\) **System** **Action:** The stand\-alone dump program waits for the operator to enter an address range\. **Operator** **Response:** Do one of the following: Enter an address range of the form R,NNNNNNNN:MMMMMMMM for a real address and V,NNNNNNNN:MMMMMMMM for virtual address translation\. NNNNNNNN is the address of the beginning of the range, and MMMMMMMM is the address of the end of the range\. MMMMMMMM must be greater than or equal to NNNNNNNN\. Press the ENTER key \(EOB\) for a default dump of all of storage\. The defaults specified at stand\-alone dump initialization time determine whether the dump is in real or virtual mode\. If message AMD009I has been issued, only real mode may be used or defaulted\.

<a id="MSG AMD009I"></a>

- **AMD009I** **CR1** **INVALID** — **Explanation:** The stand\-alone dump program tried a low speed dump of virtual addresses, but address translation cannot be performed due to a bad segment table address\. The dump program used the master segment table whose address is at PSASTOR in the prefixed save area \(PSA\) at absolute 0 as the value of control register 1, if a store\-status operation was not performed\. **Source:** Stand\-alone dump \(SADMP\) **System** **Action:** The stand\-alone dump program will reissue message AMD008A to allow the operator to enter a new address range\. **Operator** **Response:** Reply to message AMD008A, specifying a real address\.

<a id="MSG AMD010I"></a>

- **AMD010I** **PROCESSING** **ASID=asid** **ASCB=adr** **JOBNAME=jjobname** — **Explanation:** The stand\-alone dump program will attempt to dump selected paged out data\. The system issues this message for each memory that is dumped\. In the message text: asid The address space\. jjobname The name of the job\. If both ASCB fields \(ASCBJBNI and ASCBJBNS\) are zero or the first character of the job name is not A through Z, \[, $, \#, or \*, the system contains a job name of \*UNKNOWN\. adr The address of the address space control block \(ASCB\)\. **Source:** Stand\-alone dump \(SADMP\) **System** **Action:** The stand\-alone dump program continues to dump the address space\.

<a id="MSG AMD011A"></a>

- **AMD011A** **TITLE=** — **Explanation:** The message requests a dump title\. **Source:** Stand\-alone dump \(SADMP\) **System** **Action:** The stand\-alone dump program waits for the operator to enter a dump title\. **Operator** **Response:** Enter a dump title of up to 100 characters, or press the ENTER key \(EOB\) on the system console to indicate no dump title\.

<a id="MSG AMD012D"></a>

- **AMD012D** **REPLY** **I** **\(IGNORE\),** **or** **READY** **dev** **AND** **REPLY** **G** **\(GO\);** **REPLY=** — **Explanation:** The stand\-alone dump program attempted to obtain paged out data from a device, but found the device in a not ready state\. In the message text: dev The device address\. **Source:** Stand\-alone dump \(SADMP\) **System** **Action:** The stand\-alone dump program waits for the operator to enter a reply\. **Operator** **Response:** If the specified device does not exist or is not attached to the system, reply I\. Processing will ignore data indicated to exist on that device\. If the specified device is attached to the system, verify that the volume mounted is the same volume mounted when the system failed\. Then ready the device and reply G\. Processing will use selected data from the device\.

<a id="MSG AMD014A"></a>

- **AMD014A** **INTERVENTION** **REQUIRED** **ON** **DEVICE** **dev** — **Explanation:** A device is not ready\. In the message text: dev The device address\. **Source:** Stand\-alone dump \(SADMP\) **System** **Action:** The stand\-alone dump program waits for the device to become ready\. **Operator** **Response:** Ready the device\. If the device cannot be readied, rerun stand\-alone dump and, if possible, specify another address of the same device type\. **Note:** Do not attempt a store status operation before an attempt to rerun stand\-alone dump\. If the device is a 2305 Model 2 direct access device, make sure that the intervention required condition has been satisfied by doing the following: Readying the device\. Activating the STOP function on the device\. Activating the START function\. **Note:** If stand\-alone dump is rerun, certain storage locations, depending on whether a tape or direct access device is being used, may not reflect the original contents of central storage\. These storage locations may have been altered during the initial stand\-alone dump processing\.

After it is entered, the operator is prompted again and may enter another line\. 2\. SET MINASID\(minimum\) Where minimum is either all address spaces, ALL, or physically swapped\-in address spaces, PHYSIN\. Specify ALL to diagnose hangs, enabled waits, and performance problems\. If ALL is specified, the minimum dump includes certain system\-related storage ranges in all address spaces\. This dump provides enough first\-failure data to debug most system problems\. Because of the large amount of data dumped, the time for the dump may be excessive\. Specify PHYSIN to diagnose coded waits, loops, and spin loops\. If PHYSIN is specified, the minimum dump includes storage in address spaces that are physically swapped\-in\. This dump takes less time\. Because of the storage not in the dump, the dump may not contain enough first\-failure data to diagnose the system problem\. If this is the case, recreate the system problem, and request MINASID with ALL\. When in doubt, ALL is the better choice\. 3\. LIST The stand\-alone dump program writes on the console all the dump options accumulated up to now \(message AMD067I\)\. Prompting continues\. 4\. END The stand\-alone dump program stops prompting the operator and begins dump processing\. The operator can no longer respond with dump options\.
