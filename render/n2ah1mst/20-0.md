   CSV000I REQUESTED MODULE mod IS USED RECURSIVELY
          Explanation:  A request block (RB) is requesting the serially
          reusable module mod.  The RB is on the same queue as another RB
          also requesting module mod.  An IRB (interrupt RB) could have made
          the request asynchronously.  The specify program interrupt exit
          (SPIE) macro creates an IRB.
          In the message text:
          mod       The specified module.
          Source:  Contents supervision (CSV)
          System Action:  The task ends, unless ERRET is specified.
          Application Programmer Response:  A timing problem is probably
          involved.  Resolve the timing of the requests for mod or make mod
          reentrant.
          System Programmer Response:  If the error recurs and the program is
          not in error, look at the messages in the job log for more
          information.  Search problem reporting data bases for a fix for the
          problem.  If no fix exists, contact the IBM Support Center.
          Provide the source program listing for the job.

   CSV011I FETCH FAILED FOR MODULE mod, RETURN CODE nn, [REASON CODE rr]
          Explanation:  An error occurred when the routine that fetches
          programs attempted to fetch module mod into storage during the
          processing of a LINK, LOAD, XCTL, or ATTACH macro.
          In the message text:
          mod       The name of the requested module.
          nn        The return code.
          rr        The reason code.
          The possible values for the return code and the reason code are as
          follows:
          nn
          (hex) Explanation
          0B  An error occurred during FETCH processing or in one of the
              routines that gets control as a result of FETCH processing.
          0C  Not enough storage was available for FETCH to do a GETMAIN for
              the module or control blocks.
              rr
              (hex) Explanation
              04  No storage for DATD.
              08  No storage for data extent block (DEB).
              0C  No storage for input/output supervisor block (IOSB).
              10  No storage for EXLIST.
              14  No storage for module.
              18  Unable to fix storage.
          0D  The control program found an incorrect record type in the load
              module.
          0E  The control program found an incorrect address in the load
              module.
              rr  Explanation
              20  Error converting track track record (TTR).
              24  Block is outside the module.
              28  The address constant (adcon) location is incorrect.
          0F  Either an uncorrectable input/output error occurred or an error
              in the load module caused the channel program to fail.  At the
              time of abnormal end, the event control block (ECB) can be
              found by adding X'400' to the address of the FETCH work area
              located at offset X'74' in the caller's supervisor request
              block (SVRB).  The address of the failing IOSB is located at
              offset X'528' in the FETCH work area.
              rr  Explanation
              40  I/O error on a partitioned data set (PDS).
              44  Error on a virtual data set (DS).
              48  Seek address outside extent.
          10  The control program detected a relocation error in the load
              module.
          Source:  Contents supervision (CSV)
          System Action:  The system issues system completion code X'106'.
          If ERRET was not specified in the macro, the system will end the
          task.
          Operator Response:  Start a generalized trace facility (GTF) trace,
          and re-create the problem.  Reply to message AHL100A with the
          option indicated by the message or code for the problem.  If
          register 15 contains a X'F', resubmit the job, using trace option
          TRACE=IO.
          Application Programmer Response:  See the explanation for abend
          code X'106' for a description of return code nn and reason code rr.
          System Programmer Response:  If the error recurs and the program is
          not in error, look at the messages in the job log for more
          information.  Search problem reporting data bases for a fix for the
          problem.  If no fix exists, contact the IBM Support Center.
