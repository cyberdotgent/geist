### 1.2.1 Message Format

<a id="TBLTBLUNIQ9"></a>

| id CCCnnn text | id CCCnnns text |
| --- | --- |


id a Reply identifier: It is optional. It appears if an operator reply is required. The operator specifies it in the reply. CCCnnn, CCCnnns, CCCnnnns, CCCnnnnns, CCCCnnns Message identifier. CCC, CCCC A prefix to identify the component, subsystem, or product that produced the message. The prefix is 3 or 4 characters. nnn, nnnn, nnnnn A serial number to identify the individual message. The serial number is 3, 4, or 5 decimal digits. s An optional type code, which is one of the following for most messages: **A** **Action**: The operator must perform a specific action. **D** **Decision**: The operator must choose an alternative. / **E Eve**n**tual a**ction: The operator must perform action when time is available. I Inform**a**t**ion: No op**erator action is required. Most information messages are for a programmer. **S** **Severe** **error**: Severe error messages are for a programmer. W Wait: P**roce**ssing stops until the operator performs a required action. For messages with the prefix CNLC, the type codes indicate the severity of the detected error and are: **E** **Error** **I** **Information** **S** **Severe** **W** **Warning** For messages with the prefix IGW01, the type codes indicate the severity of the detected error and are: **E** **Error**: Return code 8 **I** **Information**: Return code 0 **S** **Severe**: Return code 16 **T** **Ending**: Return code 12 **W** **Warning**: Return code 4 text Text: The text provides information, describes an error, or requests an operator action.' Messages with the prefix IDA are preceded by a 2-digit severity code: **04** **Warning**: Processing may be successful. **08** **Error**: Processing may fail. **12** **Serious** **error**: Processing will probably fail.: Some messages have asterisks (*) before or after the message identifier. Two asterisks after the message identifier for IDC messages indicates a second-level message that further explains a preceding message.
