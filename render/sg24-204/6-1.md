## 6\.1 Security Related Definitions in VSE/ESA

<a id="HDRCICSSEC"></a>

We need to discuss three types of CICS related security: BIND, LINK and USER security\.

- **Bind Security**

Bind\-time security is the CICS security that can be applied when a request to establish a session is received from or sent to a remote system\.

- **Link Security**

Link security provides the lowest level of resource security for intercommunication links\. It limits a remote system's authorization to attach your transactions and access your resources\.

To specify link security for a connection between a CICS client and CICS/VSE you can use either of the following methods:

1\. *Using the link definition\.*

Use the OPERSECURITY and OPERRSL options of the CEDA DEFINE SESSIONS command to specify security keys for each set of sessions used by the connection\.

**Note:** If you use this method, CICS does not perform a signon for the link, even if you specify the SECURITYNAME parameter in the CONNECTION definition\.

2\. *Using the CICS signon table*

On the SECURITYNAME option of the CONNECTION definition, specify a user ID for the link\.

Define the authority of the link user ID in either of the following ways:

Code a DFHSNT TYPE=ENTRY macro in the CICS signon table\. Define a profile to your External Security Manager, if you use one\. \(If you use an ESM, you have to code a DFHSNT TYPE=\(ENTRY, DEFAULT\) macro in the SNT\.\)

Users of the connection will be able to access only those resources that the link is authorized to access, that is, resources with matching RSL keys\.

If you use neither of these methods, users of the connection are able to access unprotected resources only, that is, resources with the RSL key PUBLIC\.

- **User \(attach\-time\) Security**

defines how individual users of an intercommunication link are to be checked

affects the resources that individual users are able to access\.

If you specify LOCAL user security all potential users share the authority of the link user ID\. Otherwise you have to define entries for users of client workstations, either in the CICS signon table, or to your External Security Manager \(ESM\)\.

You specify the level of user\-security for a CICS client to CICS server link on the ATTACHSEC parameter option of the CONNECTION definition that defines the client to CICS/VSE\. Valid values of ATTACHSEC for CICS client \- System/390 links are LOCAL and VERIFY\.

If a client does not support VERIFY attach\-time security, you must specify ATTACHSEC\(LOCAL\) on the CONNECTION definition, and rely on link security\.

**Note:** Do not specify preset security when defining client virtual terminals or models used for autoinstalling virtual terminals\. Preset security is not supported for virtual terminals because attach\-time security is used to verify users of CICS client\-CICS/VSE links\.
