## 6\.3 Transaction Server for OS2 Security

<a id="HDRCOSSEC1"></a>

User authorization for the Transaction Server for OS2 can be controlled by means of:

- the CICS Signon Table \(SNT\), or
- the User Profile Management \(UPM\) facility of OS/2\.

The SNT method is the default\. If you select UPM, the SNT is disabled\. You can also specify that no security manager is to be used\. In this case you must use a user exit to validate user IDs and passwords\. You can select which method to use through the Security Manager field in the SIT\.

Both the SNT and UPM methods allow the system administrator to:

- add a new user ID to the system
- delete a user ID from the system
- update a user's details\.

In both methods, users sign on to CICS by entering their user ID and password\.

If you choose to use the Signon Table users do not need to sign on, but if they don't they can't use secure transactions\.

User Profile Management \(UPM\) provides an alternate method of security authorization\. You can select UPM as the security method via the Security Manager field in the SIT\.

The SNT security involves validation of a user ID and password, which then determines the privilege level of the user\. UPM security authorization is external to CICS and involves logging the CICS user on to UPM\. UPM is then queried for user privilege level and profile information\.

Hence, when UPM is being used, a UPM logon is performed during the time a user signs on to the Transaction Server for OS/2\. The CICS user is unaware that he or she is being logged on and off UPM\.

Before signing on to the Transaction Server for OS/2 a user must not already be signed on to UPM with the same user ID\.

For details please refer to the *CICS OS/2 Customization Guide*\.
