### 5\.2\.1 Connecting Directly to CICS/VSE

<a id="HDRCLIOS2"></a>

To connect CICS Client for OS/2 directly to CICS/VSE, you need to:

- Set up Communications Server on the workstation
- Set up the CICSCLI\.INI file on the workstation
- Set up the CICS/VSE system

The installation and configuration from the Communication Server is exactly the same as for the Transaction Server for OS/2\. Please refer to ["Setting up Communications" in topic 4\.1\.1](4-1-1.md) and follow the description in detail\.

```
        ___ Caution ________________________________________________________
       |                                                                    |
       | Be very careful if you are installing CICS Client for OS/2 into a  |
       | workstation that already has a CICS for OS/2 server installed.     |
       | Both products have some files of the same name, therefore you must |
       | ensure that the installation of the client does not affect the     |
       | server. This is particularly important with respect to the LIBPATH |
       | setting. It is not recommended that you install both CICS client   |
       | and CICS for OS/2 server on the same workstation, unless you are a |
       | software developer familiar with problems of this sort.            |
       |                                                                    |
       |____________________________________________________________________|
```

In our example we use the same definitions for the communications as described in the previous chapter\. If you want to have more than one connection to CICS/VSE at the same time, you need to define additional connections with different LU names\. \>\> ***CICSCLI\.INI File Definitions*** \<\<

To set up the CICS client you need to edit the **CICSCLI\.INI** file \.\.***\\cicscli\\bin***\) and change the required parameters\.

Below are shown the important parts of our CICSCLI\.INI file \(the whole file is listed in ["CICS Client File for OS/2" in topic B\.1](b-1.md)\)\.

<a id="FIGCLNT40"></a>

```
    __________________________________________________________________________ 
   |                                                                          |
   |   Client = *                      ; Auto-install client on the server    |
   |      MaxServers = 1               ; Only allow one server connection     |
   |      MaxRequests = 20             ; Limit the maximum server interaction |
   |      MaxBufferSize = 32           ; Allow for a 32K maximum COMMAREA     |
   |      LogFile = CICSCLI.LOG        ; Set the error log file name          |
   |      TraceFile = CICSCLI.TRC      ; Set the trace log file name          |
   |      DosMemory = 48               ; The DOS client's memory pool size    |
   |                                                                          |
   |__________________________________________________________________________|
```

*Figure 99\. CICS Client for OS/2 INI File: Client Section*

<a id="FIGCINI1"></a>

```
    ___________________________________________________________________________ 
   |                                                                           |
   |   Server = CICSSNA                ; Arbitrary name for the server         |
   |      Description = SNA Server     ; Arbitrary description for the server  |
   |      Protocol = SNA               ; Matches with a Driver section below   |
   |      NetName = VTAM1.PRODCICS     ; The server's fully qualified LU name  |
   |      LocalLUName = LOCLU01        ; The client's local LU name            |
   |      ModeName = SNALU62           ; The SNA communication mode name       |
   |                                                                           |
   |___________________________________________________________________________|
```

*Figure 100\. CICS Client for OS/2 INI File: Server Section*

**NetName** The first part should match the **NETID** defined in VTAM shown in [Figure 17 in topic 3\.2\.1](3-2-1.md#FIGVSEVTM1), and the second part should match the **APPLID** defined in the VTAM Application Major node shown in [Figure 19 in topic 3\.2\.4](3-2-4.md#FIGVSEVTM3)\.

**Local LU Name** should match the **L****U name** defined in the Local LU definition shown in [Figure 44 in topic 4\.1\.1](43.png) and the **Netname** defined in Connection definition shown in [Figure 26 in topic 3\.3\.2\.1](<#FIGVSECIC3>)\.

**ModeName** Should match the **MOdename** defined in the Session definition shown in [Figure 27 in topic 3\.3\.2\.1](<#FIGCICSSES>)\.

<a id="FIGCLNT42"></a>

```
    ___________________________________________________________________________ 
   |                                                                           |
   |   Driver = SNA                    ; Matches the Server's Protocol value   |
   |      DriverName = CCLIBMSN        ; Use the IBM SNA communications DLL    |
   |                                                                           |
   |___________________________________________________________________________|
```

*Figure 101\. CICS Client for OS/2 INI File: Driver Section*

- The SNA driver **CCLIBMSN** is required\.

\>\> ***CICS/VSE Definitions*** \<\<

For the CICS/VSE system you need to:

- Include the **VTPRFX** definition in the **SIT** table as shown in [Figure 25 in topic 3\.3\.1](3-3-1.md#FIGSIT)\.
- Define the **Connection** as shown in [Figure 26 in topic 3\.3\.2\.1](<#FIGVSECIC3>)\.
- Define the **Session** as shown in [Figure 27 in topic 3\.3\.2\.1](<#FIGCICSSES>)\.
- You must be sure that the **DFHLU2** \(TYPETERM\) and **LU2** \(TERMINAL\) are already created and installed in your CICS/VSE system or you must define static TERMINAL \- TYPETERM definitions as shown in [Figure 30 in topic 3\.3\.4\.3](<#FIGVSECIC5>) and [Figure 31 in topic 3\.3\.4\.3](<#FIGVSECIC6>) and start the CICS client terminal with the command: ***CICSTERM /M=typeterm*** or ***CICSTERM /N=terminal***\.
