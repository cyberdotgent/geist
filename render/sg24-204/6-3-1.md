### 6\.3\.1 Transaction Server for OS/2 Intercommunication Security

<a id="HDRCOSSEC"></a>

The Transaction Server for OS/2 can prevent unauthorized remote access by using conversation security\. The external security interface enables users to extend this protection by providing security at resource level\.

To enable protection of remote systems from unauthorized access by workstation users, the Transaction Server for OS/2 uses conversational security to send a user ID and password with each DPL, DTP, function shipping, or transaction routing request\.

To set up Transaction Server for OS/2 intercommunication security you have to: 1\. specify V \(verify\) for the Attach security field in the TCS entry for a remote system

2\. specify YES in the Conversation security field of the Communications Server/2 Partner LU definition for the remote system

The above two steps establish conversation security for attach requests in either direction between the two systems\. The current user ID and password is sent to the remote system with each ISC request\. The user ID and password are used by the remote system to control access to its resources\. For the Transaction Server for OS/2 the external security interface enables user routines to provide resource\-level security as required\.

For guidance on setting up security when multiple Transaction Server for OS/2 systems on a LAN access a remote CICS on System/390 system, see ["Security for Access from Transaction Server for OS/2 to CICS/VSE"](6-4.md) [in topic 6\.4](6-4.md) below\.

The external security interface is available for those who have additional security requirements not provided by Transaction Server for OS/2\. A user\-replaceable program is shipped which is called at four points: \(1\) User signon, \(2\) Task attach, \(3\) Resource access, and \(4\) signoff\.

For full details of these exits, including the parameter list and controls provided, see the *CICS for OS/2 Customization* manual\.
