## 3\.2 Setting up VTAM

<a id="HDRVSEVTAM"></a>

In our configuration we used **SNA Advanced Peer\-to\-Peer Networking \(APPN\)** for the connections to the Communication Server for OS/2 and additionally a Switched Major node including an independent LU definition for the Microsoft SNA Server 3\.0 for Windows/NT\.

APPN is an extension to SNA for peer communications and is the base for future SNA enhancements\. APPN builds on the low\-entry networking \(LEN\) architecture and advanced program\-to\-program communication \(APPC\) to offer dynamic networking\. The purpose of Advanced Peer\-to\-Peer Networking \(APPN\) is to:

- reduce system definition
- enable centralized and/or decentralized network management and control
- enable continuous operation and availability through dynamic definition of resources and routes\.

The main characteristics of an APPN network are its dynamic capabilities\. APPN has no required hierarchy\. APPN can establish highly dynamic networks where nodes can connect and disconnect as needed, and session routes can be determined according to the current state of the network\.

In our case this means that we do not need to define PUs and LUs for each OS/2 workstation which attaches to VSE/ESA through the Communication Server/2\.

For Windows NT, PU and LU definitions are required since we use the Microsoft SNA Server for Window NT and there is no APPN support for mainframe SNA connections in the SNA Server\. Had we used the IBM Communications Server for Windows NT we could have used equivalent definitions to the ones we set up for OS/2\. The IBM Communications Server for Windows NT does support APPN\.
