### 3\.2\.1 VTAM Startup List

The following figure shows the settings used in our VTAM startup book\. It is based on ATCSTR00 which is shipped in ICCF library 51\. We copied it and added the highlighted parameters\.

In our case the VSE/VTAM startup book is called ATCSTRMI and we use the CONFIG=MI parameter\. In the VTAM startup this is reflected by the LIST=MI parameter \(see [Figure 23 in topic 3\.2\.8](3-2-8.md#FIGVSEVTM6)\)\.

<a id="FIGVSEVTM1"></a>

```
    ___________________________________________________________________________ 
   |                                                                           |
   |   CATALOG ATCSTRMI.B                                                      |
   |   SSCPID=1,                                                              C|
   |   SSCPNAME=SSCP0001,                                                     C|
   |   NETID=VTAM1,                                                           C|
   |   HOSTSA=12,                                                             C|
   |   NODETYPE=NN,                                                           C|
   |   DYNLU=YES,                                                             C|
   |   APPNCOS=#INTER,                                                        C|
   |   HOSTPU=NODE0001,                                                       C|
   |   MAXSUBA=255,                                                           C|
   |   CONFIG=MI,                                                             C|
   |   NOPROMPT,                                                              C|
   |   IOINT=0,                                                               C|
   |   SGALIMIT=0,                                                            C|
   |   BSBUF=(28,,,,1),                                                       C|
   |   CRPLBUF=(60,,,,1),                                                     C|
   |   LFBUF=(70,,,,11),                                                      C|
   |   IOBUF=(70,288,,,11),                                                   C|
   |   LPBUF=(12,,,,6),                                                       C|
   |   SFBUF=(210,,,,20),                                                     C|
   |   SPBUF=(210,,,,32),                                                     C|
   |   XDBUF=(6,,,,1),                                                         |
   |   /+                                                                      |
   |                                                                           |
   |___________________________________________________________________________|
```

*Figure 17\. VSE/VTAM Startup Parameters*

**SSCPNAME=SSCP0001** This unique name should match the name on the host CDRM definition\. **NETID=VTAM1** This parameter is very basic\. The same name has to be used by all partners \(hosts and workstations\) using the same net\. This name is used in various places during Communication Server configuration and in the CICS client setup\. **NODETYPE=NN** When Nodetype=NN and HOSTSA are coded, the node operates as an **interchange node**\. An interchange node combines the functions of a subarea node and a network node\. It controls resources and functions as a network node in the APPN network and as an SSCP and a cross\-domain resource manager \(CDRM\) in the subarea network\.

The APPN part is used for OS/2 connections, the subarea network is used for the Windows NT connections\.

**DYNLU=YES** This parameter is required to have the ability to define independent logical units dynamically\. \(Independent LUs attaching to VTAM through a type 2\.1 PU can be dynamically defined as cross\-domain resources\. No system definition of the independent LU is required\.\)

This means that when you code this parameter you are **not** required to predefine all resources that can be accessed over adjacent link stations\. The LUs of the OS/2 based workstations need no VTAM definition in VSE/ESA\.

**APPNCOS=\#INTER** An APPN class of service for LU\-LU sessions that specifies a general, interactive class of services that uses high transmission priority, and for which short delay is considered more important than high bandwidth and low cost\.
