# B.0 Appendix B.  NDIS MAC Driver Messages

<a id="HDRAPB"></a>

This appendix contains messages that can be received from the NDIS MAC driver. The messages are either displayed or logged to a file.

The term *Slot* *nn* appears in several messages. It is used to identify an adapter in the computer based on its slot location and to identify the port on the adapter. Therefore, the first *n* refers to the slot and the second *n* refers to the port. The port is identified as either A or B (shown on the label located in the center of the adapter interface). For example, 1A corresponds to port A on the adapter in the first slot of the computer.

See Table A [-1 in topic A.0 for a](#TBLMPROKEY) description of the valid values for each NDIS MAC driver parameter.

LTC0014 .

**LTC0014** **The** **parameter** **values** **have** **forced** **the** **control-block** **size** **to** **exceed** **the** **allowable** **limit.** **Explanation:** The parameter values specified in the PROTOCOL.INI file require more space for processing than can be handled.

**User** **Action:** Reduce the value specified for either the

MaxTransmits, MinRcvBuffs, or the MulticastNum parameters to reduce the amount of storage required for the control blocks.

The control-block area can be computed using the following formula:

- 1698 + (192 × MaxTransmits) + (256 × MinRcvBuffs) + (16 × MulticastNum)

The control-block work area must be less than 64 KB. Edit the PROTOCOL.INI file if you need to change the value of any of the parameters in the formula. If more than one Dual EtherStreamer MC 32 Adapter is installed, be sure to edit the adapter's NDIS MAC driver section in the file.

LTC0025

**LTC0025** **Duplicate** **device** **driver** **statements** **exist** **in** **CONFIG.SYS.** **Explanation:** There are more than the required number of Device statements for the NDIS MAC driver (IBMMPC) in the CONFIG.SYS file. Only one occurrence of the Device statement is required to support all of the installed IBM Streamer Family adapters. Additional occurrences of the Device statement will be ignored.

**User** **Action:** Edit the CONFIG.SYS file to remove the duplicate

Device statement that loads the NDIS MAC driver.

The NDIS MAC driver has been removed. **User** **Action:** Search the hard disk for the Protocol Manager (PROTMAN.OS2). Note the path where the module was found. Edit the CONFIG.SYS file to change the Device statement for the Protocol Manager to specify the path where the module was found.

LTC0040 /

**LTC0040** **Slot** **nn:** **Using** **local** **transmit** **buffers** **to** **access** **data** **above** **16** **megabytes.** **Explanation:** The device driver has detected more than 16 megabytes of RAM in the computer, and the adapter is either a 16-bit adapter or is located in a 16-bit system slot. The device driver will copy any frame data located above the 16 MB address limit to local transmit buffers.

OS/2 2.**0 Us**e**rs:** **Early** versions of OS/2 2.0 will only indicate that at least 16 MB of RAM exist in the computer. If your computer has exactly 16 MB of RAM, you will see this message. However, there will never be any data above the 16 MB addressing limit to copy into local buffers. **User** **Action:** This is an informational message only. No action is necessary.

LTC0041

**LTC0041** **Slot** **nn:** **Overriding** **MAXTRANSMITS** **in** **PROTOCOL.INI** **with** **a** **value** **of** **xx.** **Explanation:** The amount of local memory needed to hold all possible queued transmit frames, MAXTRANSMITS * MAXTXFRAMESIZE, is greater than 128 KB. The device driver has reduced the MAXTRANSMITS value to allow the maximum number of transmit frames to fit within the default 128 KB of local buffer space. **User** **Action:** Ensure that the values specified for MAXTRANSMITS and MAXTXFRAMESIZE are accurately specified in PROTOCOL.INI. If not specified, they should both be added with appropriate values.

The default values for these parameters in OS/2 are MAXTRANSMITS = 31 and MAXTXFRAMESIZE = 18000, which exceeds the 128 kilobytes allocated by the device driver for the local transmit buffer space. These local transmit buffers are needed when more than 16 megabytes of system memory is detected, and this IBM Streamer Family adapter is unable to access above 16 MB.

A new PROTOCOL.INI parameter (for example, LOCALBUFFSEGCNT = 4) can be used to change the amount of storage used for the local transmit buffers. It can be set from 1 to 16, and defaults to 2 if not specified. Note that 64 KB of system memory are used for each local buffer segment configured with this parameter.

LTC0042

**LTC0042** **OEMHLP** **could** **not** **be** **accessed.** **Explanation:** The IBM Streamer Family adapter device driver was unable to determine the amount of system RAM in the computer. **User** **Action:** Contact your customer service center.

LTC0044

**LTC0044** **The** **configuration** **values** **have** **forced** **the** **control-block** **size** **to** **exceed** **the** **available** **memory.** **Explanation:** The configuration parameters specified require more space for processing than can be handled with the available system memory.

**User** **Action:** Reduce the value specified for either the

MaxTransmits, MinRcvBuffs, or MulticastNum parameters to reduce the amount of storage required.

The following formula can be used to compute the maximum value:

- H(i) = RCVAREA(i) + ALLOCSIZECB(i)

Where:

- **H** is the value computed for each Dual EtherStreamer MC 32 Adapter. The sum of all H(i) values must be less than 1 MB.
- **i** is the total number of Dual EtherStreamer MC 32 Adapters installed in your computer.
- RCVAREA = MinRcvBuffs × SizWorkBuf
- ALLOCSIZECB = 1698 + (192 × MaxTransmits) +

(256 × MinRcvBuffs) + (16 × MulticastNum)

The value of ALLOCSIZECB(i) must be less than 64 KB.

If you need to change the value of any of the parameters in the formula, edit the PROTOCOL.INI file. Change the parameter values in the NDIS MAC driver section for the adapter.

LTC0047

**LTC0047** **Could** **not** **determine** **the** **system** **I/O** **bus** **type.** **Explanation:** The Dual EtherStreamer MC 32 Adapter NDIS MAC driver was unable to determine the type of I/O bus designed into the computer system. It is looking for a Micro Channel bus. **User** **Action:** Make sure your system is based on a Micro Channel bus and contains an industry standard BIOS. Contact your customer service center.
