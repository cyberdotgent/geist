<a id="HDRDESAREA"></a>

[Figure 11](10.png) illustrates the logical configuration of a network in which you want to simulate the subareas in an adjacent domain. In this situation, logical units in the adjacent domain drive the application in the system under test.

![Resource 11](11.png)

The physical configuration that corresponds to these logical

configurations is shown in Figure 13. This configuration is known as direct-attach.

<a id="DIRE1"></a>

```text
   |Figure 13. Physical Configuration for Subarea Simulation Using One Host           |
```

You use the direct-attach configuration to simulate the following:* SNA subareas such as host access methods (SSCPs) and NCPs Physical and logical units associated with the host or NCP subareas <> Type 2.1 nodes that are channel attached to an NCP.

When you use the direct-attach configuration, you cannot simulate terminals in the same domain as the system under test or cross-domain links between the NCP in the system under test and a simulated NCP. TPNS uses the transport mechanisms of the network to send the traffic from the simulated logical unit to the system under test.

In the direct-attach configuration, TPNS needs its own channel adapter to an NCP that TPNS shares with the system under test. It does not require a TPNS control program. However, you must configure the communication controller with multiple channel adapters so that more than one of the adapters can be active simultaneously. This configuration allows TPNS and

the system under test to communicate with the NCP concurrently. TPNS will

not control NCP resources (lines, terminals, and so on).
