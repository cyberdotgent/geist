### 3\.1\.2 Regression Tests

Regression tests verify that old functions still operate correctly after

you have added new functions or made other changes to the system\. You can use this type of test to answer the question "Does it *still* work right?" For example, you could use a regression test to determine if you had introduced errors into your network by installing the latest version of your application or by changing your network configuration\. There are many advantages to using TPNS in a regression test:

- TPNS scripts are repeatable\. Once you have created a TPNS script, you can save it in a testcase library for future use\.
- You can use TPNS scripts to check for errors in system responses\. You can define logic tests to compare the actual response against the expected response\. If there is a discrepancy, the script can handle the error or write error messages to the operator console or the log data set\.
- TPNS can run automatically\. Once you start the TPNS job, execution parameters and operator commands in the scripts or in NetView CLISTs can control TPNS operation\. A TPNS script can even end the simulation when all the testcases are complete\.
- You can use the Log Compare Utility to compare the 3270 display records from two TPNS log data sets\. This comparison enables you determine how a change to the system affects the behavior of IBM 3270 Information Display Systems without having to compare the log data sets manually\.

You do not need to restrict TPNS to large comprehensive regression tests\. You can easily use TPNS with existing testcases to test routine maintenance changes to your system\.
