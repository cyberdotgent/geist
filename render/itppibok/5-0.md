# 5.0 Determining Your System Configuration

<a id="HDRCON"></a>

This chapter discusses how to configure your system for a TPNS test. When you configure your system, you determine what hardware and software <> resources you need and decide how to arrange them. Once you have configured your system, you can begin coding the network definition statements and the message generation decks for your test.<> Before you read this chapter, be sure that you are familiar with the definitions of the following SNA terms and TPNS concepts:

**Logical** **unit** **(LU)** A logical unit is a port through which an end user accesses the SNA network to communicate with another end user or the system services control point (SSCP). **System** **services** **control** **point** **(SSCP)** An SSCP is the managing entity for the network resources in an SNA domain. **Session** A session is a logical connection that enables two network addressable units to communicate with each other (for example, an ABOUT LU-LU session or an SSCP-LU session). Each half of a session is a half-se***ssion.*** **Domain** A domain is the collection of all the resources controlled by a single SSCP. A multipl***e-domain networ***k ***contai***ns several domains, each controlled by its own SSCP. **Subarea** <> A subarea is a subset of the resources contained in a domain. All <> of the resources in a subarea have a common subarea address. The subarea is the basic unit of routing in an SNA network. **Terminal** **simulation** In TPNS, terminal simulation occurs when TPNS simulates a terminal in the same domain as the system under test. **Subarea** **simulation** In TPNS, subarea simulation occurs when TPNS simulates an entire subarea in another domain communicating with the system under test. **Domain** **simulation** In TPNS, domain simulation occurs when TPNS simulates an entire domain, including an SSCP, communicating with the system under test. **Adjacent** **domain** In TPNS, an adjacent domain is a simulated domain that is directly <> attached by a channel or cross-domain link to the domain of the system under test. **Nonadjacent** **domain** In TPNS, a nonadjacent domain is a simulated domain that is not directly attached to the domain of the system under test. The traffic between resources in a TPNS nonadjacent domain and the system under test must be routed through a TPNS adjacent domain. **Cross-domain** **link** <> In TPNS, a cross-domain link is a real or simulated Synchronous <BOOK> Data Link Control (SDLC) line connecting two NCP nodes that are contained in separate domains.
