#### 6.3.3.1 Simulating Host Subareas and Resources

```text
   When it simulates a domain, TPNS automatically performs all of the <>    functions of the host subarea.  When necessary, SSCPs simulated by TPNS *    can generate and send cross-domain commands and responses to real SSCPs in
   the system under test.  The simulated SSCPs can also interact with
   simulated logical units during session initiation and termination.

   To define a host subarea to be simulated by TPNS, you can code the
   following statements:<>
   The SSCP statement defines the host subarea to be simulated.  You use
   operands on this statement to specify additional characteristics of
   the host subarea and to provide default values for subsequent LU
   statements.<BOOK>
   The PATH statement, when coded after an SSCP statement, defines the
   network routing from the simulated host subarea to other subareas.(
   The MODETAB, MODEENT, and MODEEND statements define a logon mode table <>
   for a simulated host subarea.  A logon mode table contains entries
   that provide session parameters for the logical units owned by the
   SSCP and is used when a logical unit in a simulated domain requests
   session initiation.*
   The COSTAB, COS, and COSEND statements define a class of service table <>
   for a simulated SSCP.  The class of service table contains entries
   <>        that provide lists of virtual routes to be used for session traffic.

   The LU statement defines a host logical unit.  This logical unit can <>
   be an application or a logical unit locally attached to an SSCP.  Each
   logical unit can generate messages to be sent to the system under
   test.)
   The CDRM (Cross Domain Resource Manager) statement defines a remote
   host subarea that can be in session with a host subarea simulated by
   TPNS.

   The CHANL statement defines a direct channel attachment between a host
   subarea simulated by TPNS and an NCP in the system under test.
```
