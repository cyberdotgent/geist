## D.1 Integrating TPNS Into Communication Network Management

You can integrate TPNS into a scheme for managing a communication network with other IBM products, including the following:

NetView program NetView Performance Monitor (NPM) Network Communications Control Facility (NCCF) Network Logical Data Manager (NLDM) Network Problem Determination Application (NPDA). TPNS contains special support that enables it to communicate with these <BOOK> products. Alternatively, you can use it by itself to monitor portions of <> the network. In addition, you can run TPNS from a NetView terminal. For more information about using the operator interface between the NetView program and TPNS, refer to ["Using the Operator Interface between TPNS and](8-5-4.md) [HDRRUNNET](8-5-4.md) <BOOK> <> <> <SC30-32 [89> <> <TPNSOP>](#LNK) the NetView Program" and to TPNS Operation. When you use TPNS to manage a communication network, you generally define a small network (for example, one LU, PU, and LINE). You do not need to run TPNS in a stress mode. This way, TPNS can run continuously during production hours with little impact on the system. Depending on your situation, you can use VTAMAPPL, terminal, or subarea simulation to manage a communication network. However, if you use the VTAMAPPL configuration, remember that there are no PU statements in the / definition, so SSCP-PU data flows are not available. However, VTAMAPPL definitions can make using TPNS much more practical for logical unit simulation. You may want to use subarea simulation in some cases to simulate an NCP " owned by a real host. This would enable you to send SSCP-PU flows from a simulated NCP, as well as from simulated PU Type 2 nodes.
