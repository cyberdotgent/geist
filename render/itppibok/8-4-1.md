### 8\.4\.1 Using MVS

On MVS, you start TPNS as a batch job or as a normal procedure\. The

statements you use in the execution JCL depend on the physical configuration of your system:

- If you are using a link\-attach configuration, you need to load the TPNS control program into the communication controller\. Use the PREFIX execution parameter to specify the first five characters in the name of the TPNS control program load module on the EXEC statement\. Use the SYSUT1 DD statement to define a data set used by the communication controller loader program\. Finally, use the DDCTLR*xx* DD statement to define the communication controller unit address for the TPNS control program\.
- If you are using a direct\-attach configuration, you need to load the NCP into the communication controller\. Use the NCPDD*yy* DD statement to define a data set that contains the NCP load module and the resource resolution table \(RRT\)\. Use the CHANDD*yy* DD statement to define the communication controller unit address for the NCP\.
- If you want to perform cross\-domain simulations concurrently over a channel and cross\-domain links, you can define any combination of TPNS communication controllers and NCP communication controllers by using the SYSUT1, DDCTLR*xx*, NCPDD*yy*, and CHANDD*yy* DD statements\.
- If you are using VTAMAPPL, you do not need the SYSUT1, DDCTLR*xx*, NCPDD*yy*, or CHANDD*yy* statements since a communication controller is not required\.

Refer to [TPNS Operation](<DOCNUM/SC30-3289/CCONTENTS>) for an example of the JCL to run TPNS on MVS in each of these configurations\.
