### 6\.3\.6 Simulating X\.25 Packet\-Switched Networks

TPNS provides three different types of simulation for X\.25 packet\-switched networks:

- TPNS appears as data circuit\-terminating equipment \(DCE\) to the system under test and simulates data terminal equipment \(DTE\) in communication with the system under test\.
- TPNS appears as DCE to the system under test and simulates a packet\-switched network between real DTEs\. This is referred to as *passthrough simulation*\. Passthrough simulation is independent of end\-to\-end protocols \(such as SNA\) or the types of DTEs involved\.
- TPNS appears as DTE to the system under test, which can be a real packet\-switched network \(including an SNA backbone network\)\. TPNS can simulate a variety of DTEs, including the following:

SNA terminals SNA subareas X\.25 native equipment TWX or 3103 terminals\.

For complete information about each of these types of simulation, refer to

[Defining TPNS Networks](<DOCNUM/SC31-6008/CCONTENTS>)\.

**Note:** TPNS X\.25 network simulations are consistent with the IBM interpretation of the 1980 CCITT Recommendation X\.25 when the multichannel link \(MCH\) is defined as a 1980 level MCH; otherwise, the simulations are consistent with the IBM interpretation of the 1984 CCITT recommendation X\.25\.

You use the following network definition statements to define X\.25 packet\-switched network resources to be simulated by TPNS:

- The CALLDATA \(call request data\) statement describes the facilities and user fields for calls made by TPNS on a given logical channel\.
- The PADPARMS statement specifies the parameters for packet assembly/disassembly \(PAD\)\. This enables nonpacket mode terminals to exchange data in the packet mode\.
- The MCH statement defines the physical line address used on an X\.25 packet\-switched network interface that can carry traffic for multiple logical channels\.
- The LCH \(logical channel\) statement defines the remote endpoint of the virtual circuit to be carried on the logical channel, the type of virtual circuit, and packet\-level parameters\. This statement also specifies the logical channel number \(LCN\) and the logical channel group \(LCGN\)\.

You must use LCH statements to define communications between a DTE simulated by TPNS and the system under test\. You must use two LCH statements to define passthrough permanent virtual circuits\. You do not need LCH statements to define passthrough switched virtual circuits\.

- The VC \(virtual circuit\) statement matches up the two logical channels for passthrough permanent virtual circuits\.
