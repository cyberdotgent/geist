#### 6.3.3.2 Simulating NCP Subareas and Resources

TPNS can simulate entire NCP subareas in an SNA domain. The simulated NCP subarea and its underlying resources can be controlled by a simulated host or by a real host.

**Note:** You must use a communication controller containing a TPNS control program for simulations involving real host ownership of a simulated NCP <BOOK> subarea. You cannot simulate NCP subareas owned by a real host if the host running TPNS is channel attached to the system under test. For more

<BOOK> <> <> < [SC31-6008> <> <TPNSDF>](#LNK) information, refer to Defining TPNS Networks. To define an NCP subarea to be simulated by TPNS, you can code the following statements:) The CNTRL statement defines an NCP subarea (PU Type 4) to be simulated by TPNS.<BOOK> The PATH statement, when coded after a CNTRL statement, defines the network routing from the simulated NCP subarea to other subareas. The LINK statement defines a physical link between a simulated NCP subarea and a real subarea. The LINK statement can also define a simulated link between two simulated subareas. The LINE statement defines a peripheral link within a simulated NCP subarea. PU and LU statements following the LINE statement define the physical and logical units to be simulated on the line.( The PU statement, when coded after a LINK statement, defines a link <BOOK> station for an adjacent NCP subarea. When coded after a LINE statement, the PU statement defines a physical unit within the simulated NCP subarea. The LU statement defines a secondary logical unit within the NCP subarea. Each logical unit can generate messages to be sent to the system under test.
