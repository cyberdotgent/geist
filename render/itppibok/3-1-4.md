### 3.1.4 Stress Tests

Stress tests try to find problems in interactions and resource contentions by driving the system to extremely high transaction rates. These types of problems might be missed by single terminal simulations. You can use stress tests to answer the question "What will break first " <BOOK> For example, you might use a stress test to determine how many users can log on to your system before it is overloaded.

It is nearly impossible to conduct a stress test on an online system <BOOK> without a tool like TPNS. Using TPNS, you can generate controlled message traffic at controlled rates without worrying about coordinating terminal operators or risking a possible system crash.

If you are conducting a stress test, you should run TPNS in a different host than you are using for the system under test. Otherwise, the computer resources needed for TPNS operation can impact your results.
