### 8.5.1 Using TPNS Operator Commands

You can use TPNS operator commands to control various aspects of a simulation. For example, you can use operator commands for the following types of tasks: Initializing the network Starting, stopping, and canceling network resources Displaying the current status of a network resource Altering the values of network parameters Restarting message logging Transmitting alerts or other unsolicited RUs from simulated terminals or controllers to a real host<> Obtaining online response-time statistics for a specified resource Entering console recovery mode Loading a communication controller with a TPNS control program Stopping TPNS.

To use operator commands effectively, you need to understand how they affect the resources simulated by TPNS.* From the user's standpoint, TPNS consists of networks with variable numbers of: Lines Terminals Devices VTAM applications (VTAMAPPL) Multichannel links (MCH) Logical channels (LCH)

<> IBM Token-Ring Network ports (LPORT) Logical link stations (LLS) Type 2.1 node resources Cross-domain resources. Each resource is represented by a control block. TPNS operator commands operate on these control blocks. You determine which resource is affected by the operator command by <BOOK> specifying a unique resource name on the command. If the name of the <BOOK> resource is not unique (for example, you assigned the same name to <> terminals on different lines), you must qualify it by preceding it with / the name or names of the next higher-level resource or resources. Note <> that if you assign unique names to the resources in your network, you do not need to qualify the names on the operator command. You can operate and control networks independently of each other so that <> you can cancel one network without affecting any other networks. You can also change all networks with one command.
