### A\.2\.1 User Considerations

The following list summarizes the command and language syntax changes that occur with TPNS Version 3 Release 2, as well as other changes that might affect TPNS users:

- You can now code the following new STL statements:

VERIFY, to support the logging of VERIFY records in the log data set SETRH, to modify the request/response unit header SETTH, to modify the transmission header SNACMND, to support SNA commands\.

- You can now code the STL C2X function, to convert a string variable to its hexadecimal representation\.
- The following names are now reserved words in STL:

In STL, you can now do the following:

Check for exact offsets using the INDEX function on an ONIN or ONOUT statement\. Before, coding ONIN INDEX\(SUBSTR\(RU,5\),'x'\)\.\.\. would return the index starting at position 1 in the RU, not at position 5\. Now, coding this statement returns the index starting at position 5\. If your programs depend on the old value returned, you may need to change your code\.

Displaying the screen image buffer by the statement LOG DISPLAY\. Coding LOG SCREEN or LOG BUFFER now logs the device buffer\.

Code string constants as the first argument to the INDEX function\.

Perform string concatenation on the left side of an operator involving a non\-constant string expression\.

Code an expression without regard to the left and right side\. For example, you can now code IF 5=A THEN \.\.\.\.

Code DO\-END groups within ONIN, ONOUT, and ON SIGNALED statements\.

Include string constants or concatenation in the first argument specified to UTBLSCAN\.

Have TPNS statements always added to the sequential output data set\. Coding NOTPNS before prevented this\.

Have STL statements always added to the SYSPRINT output data set\. Coding NOSOURCE before prevented this\.

Code integer expressions for the RANDOM and RNUM functions' low and high values\.

Declare multiple variables on one BIT, INTEGER, or STRING statement\.

Specify the format of the date output and request the date for a specified number of days in the future for the DATE function\.

Have the COFF function, when coded in an assignment statement, return the offset relative to screen position 1\. Before, coding the COFF function in an assignment statement returned the offset relative to screen position 0\.

- You can now code two resource names on the following commands for the Log Compare Utility:

DEV MSGTXT LINE LU NODE NTWRK TERM VTAMAPPL\.

- TPNS/ATP now supports the EQU and COPY statements in MFS source code\.
- You need to convert the VSAM screen definition file \(SDF\) to a format that allows a 16\-byte key for the TPNS/ATP utility programs\. You can do this by running the VSAM IDCAMS job to convert the SDF file to the new format\. This JCL is supplied\. Also, TPNS automatically converts the TCF file from an 11\-byte format to a 16\-byte format whenever you

access the file with the TPNS/ATP Editor\. See [TPNS Script Generating](<DOCNUM/SC30-3453/CCONTENTS>) [Utilities](<DOCNUM/SC30-3453/CCONTENTS>) for more information\.

- PF6 is now assigned a function in ITPECHO\.
- You can now code the EXTERM and EXDEV commands for the Loglist Utility\. See [TPNS General Utilities](<DOCNUM/SC30-3290/CCONTENTS>) for details of these commands\.
- You can now code the EXTERM command for the Response Time Utility\. See [TPNS General Utilities](<DOCNUM/SC30-3290/CCONTENTS>) for details of this command\.
- BRANCH statements can now be executed within an execute deck\. If you coded an execute deck and relied on the fact that the BRANCH statement acts as a delimiter and terminates processing of the deck, you must recode the deck\.
- You can now specify the BLOCK=\(*b,p*\) operand on the NTWRK, CNTLR, LINK, and PU \(PU Type 4\) statements to enable TPNS to send and receive blocked PIUs to and from type 4 PUs\.
- The CNTRS operand on the NTWRK statement now specifies the minimum number of counters used for each line, terminal, and device when user exits are specified\. When user exits are not specified, the CNTRS operand is ignored\. This provides TPNS with the ability to allocate counters dynamically\.
- You can now specify the LLS operand on the LINK statement to enable Token\-Ring lines to be used on cross\-domain links\.
- You can now code counters for the random number specification on the SET statement\. See [TPNS Language Reference](<DOCNUM/SH20-2489/CCONTENTS>) for details of this change\.
- You can now code counters for the random number specification on the

$RNUM$ data field option\. See [TPNS Language Reference](<DOCNUM/SH20-2489/CCONTENTS>) for details of this change\. This also applies to the LENG operand on the TEXT statement and the TIME operand on the WAIT and DELAY statement\.

- You can now specify the LOCTEXT operand on the IF statement\.
- You can now specify the CONVERT operand along with the TEXT operand on the DATASAVE statement\. You can also code D, TH, RH, and RU values for the LOC operand when WHEN=IMMED and for the DATASAVE statement\.
- You can now code D, TH, RH, RU, and \(*row,col*\) values for the $RECALL$ data field option\.
- You can now specify two new operands for the $DATE$ data field option\. These allow you to specify the format of the date output and request the date for a specified number of days in the future\.
- You can now specify the THROTTLE operand on the LU and DEV statement to support multiple message generation for LUs\.
- Threshold values on the PATH statement were increased to 524287\.
- You can now specify a value of 4 for the DEF operand on the RTM statement\.
- You can now specify the CPSESCAP and CPINIT operands on the PU21 statement to provide CP\-CP session node support\.
- You can now specify the CPSESS operand on the ADJNODE statement to indicate that the adjacent node has network node capabilities\.
- You can now specify the HWSUBFLD operand on the TERM, DEV, PU, and LU statements to support the Network Asset Management function\.
- EXTFUN=YES is now the default value for LU2\.
- You can now specify the following user exit operands on the NTWRK statement:

INEXIT OUTEXIT NCTLEXIT UCMDEXIT LNEREXIT UXOCEXIT\.

- If you use a TPNS controller, you may need to modify your TPNS control program\. The following list details the changed macros and operands:

You can now code ALCI for the TYPE operand of the TERM statement

You can now code ALCT for the TYPE operand of the DEV statement

You can now specify the ALCSEOM operand on the MSGTXT and TEXT statements

You can now define ALC lines with the TPNSALC macro\.

**Note:** The ALCI, ALCT, and ALCSEOM operands, along with the TPNSALC macro, are only available with the TPNS 3745 control program\.

- If you are simulating multiple networks, local storage areas in user exits are no longer preserved across calls\.
- If you are logging messages to a disk data set on MVS, you no longer need to enter the E operator command twice\.
