### 2\.3\.1 LNM OS/2 Agent Application Problems

<a id="HDREPLPRB"></a>

If you experience problems that seem to be associated with the LNM OS/2 agent application, first follow the general problem determination suggestions in ["Gathering Problem Information" in topic 2\.1](2-1.md)\. Other sources of information that may be helpful include the following:

\_\_ nettl log \(see ["Checking the nettl Log" in topic 2\.1\.2](2-1-2.md)\)

Trap numbers for LNM OS/2 agent\-initiated traps correspond to DFI message numbers\. Use the LAN Network Manager for OS/2 Version 2\.0 documentation to resolve errors reported by traps\. You will have to read the trap description to distinguish between traps with the same trap number\.

Run command return codes written to the nettl log by the LNM OS/2 agent monitor program \(lnmlnmemon\) usually correspond to DFI messages numbers in the LAN Network Manager for OS/2 Version 2\.0 documentation\. Exceptions are noted in the documentation for message 610 in [Chapter 5, "Messages" in topic 5\.0](5-0.md)\.

A "1" has been appended to the DFI message number for the messages displayed by the LNM OS/2 Agent application if there is a matching DFI number\.

Traps generated by the LNM OS/2 agent program are listed in ["LNM](4-1.md) [OS/2 Agent Application Traps" in topic 4\.1](4-1.md)\.

\_\_ Execute lnmstatus to determine the state of the LNM OS/2 agent monitor program\. Refer to the man page for lnmstatus for a description of the exit statuses provided by lnmstatus\.

\_\_ Save formatted nettl logs and the trapd\.log\.

\_\_ Save the core image or output from the dbx command\.

\_\_ Execute `ps -ef | grep lnm` to ensure that the following conditions exist:

- lnmlnmemon is running and is the parent of an instance of lnmBaseTimer and lnmlnmeint\. If it is not, refer to messages 613 and 635 in [Chapter 5, "Messages" in topic 5\.0](5-0.md)\.
- lnmlnmeint is running and is the parent of an instance of lnmBaseTimer\. If it is not, refer to message 820 in [Chapter 5,](5-0.md) ["Messages" in topic 5\.0](5-0.md)\.
- lnmlnmemgr is running\. Attempting to bring up a window will restart lnmlnmemgr\.
- lnmd is running\. The LNM OS/2 agent application fails if lnmd is not running\.
- lnmtopod is running\. The LNM OS/2 agent application fails if lnmtopod is not running\.
- No LNM for AIX processes should be direct children of the init process

\_\_ If the problem is repeatable, tracing files are extremely useful\. You can start tracing on both the lnmlnmeint and lnmlnmemon daemons\.

- Start tracing on lnmlnmeint to log the command flow between LNM for AIX and the LNM OS/2 agent program\.
- If you start tracing on lnmlnmemon you will log data which in conjunction with the log from lnmlnmeint should help resolve problems when the call stack from the core dump is not enough\.

Refer to ["Using the Tracing Command" in topic 2\.1\.3](2-1-3.md) for instructions on how to turn tracing on and off for a particular daemon\.

Before starting tracing on lnmlnmemon, ensure that lnmlnmemon has started the lnmlnmeint and lnmBaseTimer processes by entering:

`ps -ef | grep lnm`

To obtain a complete log, turn off automatic agent discovery and execute lnm\_agent\_found after executing the **kill \-30** command\.
