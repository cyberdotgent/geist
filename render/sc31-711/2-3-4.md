### 2\.3\.4 FDDI Application Problems

<a id="HDRFDIPRB"></a>

If you experience problems that seem to be associated with the FDDI application, follow the general problem determination suggestions in ["Gathering Problem Information" in topic 2\.1](2-1.md)\. Next, check the following sources of information:

\_\_ nettl log \(see ["Checking the nettl Log" in topic 2\.1\.2](2-1-2.md)\) and trapd log

\_\_ Execute lnmstatus to determine the state of the FDDI application\. Refer to the man page for lnmstatus for a description of the exit statuses provided by lnmstatus\.

\_\_ Save formatted nettl logs and the trapd\.log\.

\_\_ Save the core image or output from the dbx command\.

\_\_ Execute `ps -ef | grep lnm` to ensure that the following conditions exist:

- lnmfddimon is running and is a child of the lnmd process\.
- lnmfddimgr is running\. Attempting to bring up a window will restart lnmfddimgr\.
- lnmd is running\. The FDDI application fails if lnmd is not running\.
- lnmtopod is running\. The FDDI application fails if lnmtopod is not running\.
- LNM for AIX processes are not direct children of the init process\.

\_\_ MIB browser dump of the MIB\. If a station does not show all of its sub\-objects \(for example, path, path class, attachment\), look at a MIB browser dump of the MIB\.

To obtain MIB browser dump of the MIB:

**1\.** Select **MIB browser: SNMP** from the AIX NetView/6000 Tools pull\-down menu\.

**2\.** Select **mgmt** from the Browse MIB window\.

**3\.** Fill in the IP address and community name of the bridge\.

**4\.** Select **Start Query**\.

**5\.** Select **Save** to save the output of the dump\.
