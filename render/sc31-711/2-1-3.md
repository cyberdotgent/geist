### 2\.1\.3 Using the Tracing Command

<a id="HDRKILL30"></a>

Start tracing on one or more specific LNM for AIX daemons to log the command flow between LNM for AIX and an agent program\. Tracing is useful when you are searching for problem causes\. You can start tracing for the following daemons:

- lnmtopod
- lnmbrmon
- lnmlnmemon
- lnmlnmeint
- lnmtrmon
- lnmhubint

If SIGUSER1 \(SIGNAL 30\) is received by a daemon for which tracing is not enabled, that daemon will be stopped\.

To start tracing on a daemon, perform the following steps:

**1\.** Get the process identifier \(PID\) of the daemon by entering the following command:

`ps -ef | grep lnm_process`

where *lnm\_process* is the name of the LNM for AIX daemon, such as lnmlnmemon or lnmtrmon\.

**2\.** Turn on tracing by entering the command:

`kill -30 nnnnn`

where *nnnnn* is the process identifier \(PID\) of the LNM for AIX daemon\.

The **kill \-30** command does not terminate the specified process; it simply starts tracing for the process\.

**3\.** Turn off tracing by entering the following command:

`kill -30 nnnnn`

where *nnnnn* is the PID of the LNM for AIX daemon for which tracing is active\.

The tracing file is given a file name that identifies the process and is placed in `/tmp` directory\. For example, if you are tracing against the lnmlnmemon daemon, the name of the tracing file begins with `lnmemon`\.

The tracing file continues to be appended to by the tracing process until you turn tracing off\. To ensure that this file does not use more space in the `/tmp` directory than necessary, turn off tracing when you have finished debugging a problem\. A new tracing file is created if **lnmstop** and **lnmstart** are executed between uses of the **kill \-30** command, otherwise tracing information is appended to the current file for the process\.
