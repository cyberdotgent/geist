#### 3\.8\.4\.3 Build Serviced Objects

```
    ___ Note _______________________________________________________________
   |                                                                        |
   | Use the remainder of this step to build all CMS objects that were      |
   | serviced.  If you prefer to build CMS objects individually, then use   |
   | "Detailed Build Steps: CMS" in topic 4.3 instead of the rest of this   |
   | step.                                                                  |
   |                                                                        |
   |________________________________________________________________________|
```

**1\.** If you make any changes to the DMSNGP ASSEMBLE file, you must use VMFHASM to reassemble the file\.

<a id="TBLTBLUNIQ101"></a>

```
                                                  For more information about the DMSNGP
   vmfhasm dmsngp esa cms                         ASSEMBLE file, see the VM/ESA: Installation
 |                                                Guide and VM/ESA: Planning and
 |                                                Administration book.

   copyfile dmsngp txtft a = = fm-3C4 (olddate replace
   erase dmsngp txtft a

                                                  The COPYFILE command copies DMSNGP back to
                                                  the LOCALMOD disk.

                                                  txtft is the text file type.  txtft becomes
                                                  TXT00000 even if no updates were applied.
```

**2\.** Spool the printer and punch:

<a id="TBLTBLUNIQ104"></a>

```
                                                  Spool the printer and punch output to your
   spool prt *                                    virtual reader.  This is required, to have
   spool pun *                                    the serviced nucleus transferred to your
                                                  reader.
```

```
        ___ Note for CMS Pipelines Users ___________________________________
       |                                                                    |
       | If you have SQL/DS or ISPF or both, and are using the CMS          |
       | Pipelines interfaces to these applications you must enter the      |
       | GLOBAL command to identify the text libraries containing the       |
       | interface files before running VMFBLD.                             |
       |                                                                    |
       |                                                                    |
       |   global txtlib pipsql                                             |
       |                                                                    |
       |                                                                    |
       | pipsql is the file name of the TXTLIB containing the SQL/DS        |
       | interface files, ISPF interface files, or both.                    |
       |                                                                    |
 |     | For more information on how the TXTLIB is created and where it is  |
 |     | located, see the VM/ESA: Planning and Administration book.         |
       |                                                                    |
       |____________________________________________________________________|
```

**3\.** To rebuild all serviced parts, enter the following command:

<a id="TBLTBLUNIQ105"></a>

```
   vmfbld ppf esa cms (serviced
```

```
 |      ___ Note ___________________________________________________________
       |                                                                    |
 |     | If you would like to change the default system national language   |
 |     | for CMS you must rebuild the CMS nucleus to contain the language.  |
 |     | To do this, follow the steps in Appendix C, "Changing System       |
 |     | National Language including UCENG" in topic C.0.                   |
       |                                                                    |
       |____________________________________________________________________|
```

**Notes:**

a\. If you receive the following message:

`DMSLIO201W The following names are undefined: DMSUSRX1 and DMSUSRX2`

disregard it, because the undefined names are user exits\.

b\. If you receive the following messages:

`DMSLIO201W The following names are undefined: ISPLINK1 and ARIPRDI`

disregard it, because they are interface files for ISPF and Sequel\.

c\. If, while building the DMSCUT or DMSDFT MODULEs, you get a return code of 4 with this message, you can disregard it\.

**4\.** Review the build message log \($VMFBLD $MSGLOG\)\. If necessary, correct any problems before going on\. For information about handling specific build messages, see [VM/ESA: System Messages and Codes](<DOCNUM/SC24-5529/CCONTENTS>), or use on\-line HELP\.

<a id="TBLTBLUNIQ107"></a>

```
   vmfview build
```
