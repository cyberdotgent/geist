#### 6.1.4 Determine Requisite PTFs

Use the

function with the service requisite table and service apply status table to return the requisites for the PTFs specified. This function would be used to determine if you have all the PTFs received and/or applied that are required by a PTF you want to install.

<a id="TBLTBLUNIQ436"></a>

srvreqt *

| vmfsimsrvapps * tdata :ptf um18135 | VMFSIP2480I RESULTS FOR | TDATA :PTF UM18135 |
| --- | --- | --- |


function returns the following data:

**Field** **Data** **Definition** **:****PTF** This field contains the PTF number being processed. **:****PREREQ** This field contains a list of the PTFs in this product or component or another product or component that must be installed before installing this PTF. PREREQs satisfy the service chain. **:****COREQ** This field contains a list of the PTFs in this product or component or another product or component that must be installed before running this product or component with the PTF installed. COREQs satisfy the service chain. **:****SUP** This field contains a list of the PTFs that this PTF supersedes, or is a functional replacement of. **:****IFREQ** This field contains a list of the PTFs in another product or component that are required if the product or component is installed. **:****HARDREQ** This field contains a list of the APARs that are required to be installed for this PTF to function. These are a subset of the PREREQs that have real code intersections or functional dependencies. HARDREQs satisfy functional requisites. **:****SUBREQ** This field contains a list of the PTFs in this product or component or another product or component that are required by the requisites identified above. **:****SUBIF** This field contains a list of the PTFs in another product or component that are required by the requisites identified above if the product or component identified in the condition is installed. **:****SUBHARDREQ** This field contains a list of the APARs that are required to be installed by the PTFs listed above for them to function correctly.

**Note:** The fields :SUBREQ, :SUBIF, and :SUBHARDREQ are not in the actual table, they are output only from the

command.
