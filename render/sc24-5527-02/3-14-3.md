### 3\.14\.3 Place the Test Build Disks into Production

```
 |      ___ Note ___________________________________________________________
       |                                                                    |
 |     | If you have updated the 190 or 193 disks you should copy any new   |
 |     | and changed files to the 490 and 493 disks.  This will avoid       |
 |     | accidentally back-leveling modified files.                         |
       |                                                                    |
       |____________________________________________________________________|
```

**1\.** Use the DASD dump/restore program to copy the test CMS system disk \(490\) to the production CMS system disk \(190\)\. For performance reasons, DDR should be used instead of COPYFILE\. Also, the nucleus will be copied from the 490 to the 190 disk\.

**Note:** Use your installation back\-up procedures if you want to save a back\-up copy of the 190 disk\.

<a id="TBLTBLUNIQ269"></a>

```
 |                                                Access the CMS system disk (190) at a file
 | access 190 fm                                  mode other than S.  fm may be any unused
 |                                                file mode.

 | ddr
 | VM/ENTERPRISE SYSTEMS ARCHITECTURE DASD DUMP/RESTORE PROGRAM
 | ENTER:

 |                                                The system prompts you to enter a DDR
 |                                                control statement.

 |                                                Route messages to the console (rather than
 | sysprint cons                                  a printer).
 | ENTER:

 |                                                Enter 490 as the source minidisk for the
 | input 490 dasd mnt490                          copy.
 | ENTER:
 |                                                490 is the virtual device number of the
 |                                                test CMS system disk.  dasd will determine
 |                                                the device type of the real DASD volume on
 |                                                which the 490 minidisk resides (for
 |                                                example, 3380).  mnt490 is the label of the
 |                                                minidisk.

 |                                                Enter 190 as the target minidisk for the
 | output 190 dasd mnt190                         copy.
 | ENTER:
 |                                                190 is the virtual device number of the
 |                                                production CMS system disk you are
 |                                                creating.  dasd will determine the device
 |                                                type of the real DASD volume on which the
 |                                                190 minidisk resides.  190 must be the same
 |                                                DASD type as the 490 disk.  mnt190 is the
 |                                                label of the 190 minidisk.

 |                                                Enter the COPY control statement to copy
 | copy all                                       the entire 490 minidisk.

 |                                                DDR performs the copy and displays messages
 | END OF COPY                                    about the operation.  When the copy is
 | ENTER:                                         complete, DDR prompts you to enter another
 |                                                control statement.  At the prompt, press
 | END OF JOB                                     the ENTER key to enter a null line.  The
 |                                                system reports end-of-job status.
```


**2\.** Use the COPYFILE command to copy the test VMSES/E tools disk \(5E6\) to the production VMSES/E tools disk \(5E5\)\.

**Note:** Use your installation back\-up procedures if you want to save a back\-up of the 5E5 disk\. COPYFILE is preferred over DDR for this task because it works more efficiently with a small number of files\.
