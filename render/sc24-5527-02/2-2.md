## 2\.2 Prepare Your System for Service Refresh

<a id="HDRPREPARE"></a>

**1\.** Receive the documentation:

Receive the documentation and identify the components on the tape for the RSU Tape\. This step will also load the cumulative Apply Status Table \(*appid* SRVAPPS\) which identifies all preapplied service contained on the tapes\. These files are loaded to the 51D disk\.

<a id="TBLTBLUNIQ24"></a>

```
 |                                                rdev is the real address of the tape drive
 | attach rdev * 181                              containing the RSU Tape which must also be
 |                                                attached as 181.

   vmfins install info
```

**2\.** Determine DASD sizes for disks to receive service:

In order to receive the service from the RSU Tape, you need to have adequate space available on each component's alternate APPLY and DELTA disks\. The required sizes are identified in the product documentation \(*prodid* MEMO D\) received in the previous step\.

The following tasks, ["Prepare to Receive a Component from the RSU](2-3.md) [Tape,"](2-3.md) ["Process Additional Service," and](2-3-2.md) ["Build the New Service Level"](2-3-3.md) should be completed for each component contained on the RSU Tape\. The components should be processed in the order that they appear in the following table, using the component name \(*compname*\) listed to identify each component\. Perform each task for *ALL* components before moving on to the next task\.

**3\.** Prepare the system for service: You need to prepare the system for service each time you apply new service to your system\.

a\. As a precaution, do a complete backup of your system\. See the [VM/ESA: Installation Guide](<DOCNUM/SC24-5526/CCONTENTS>) for instructions\. b\. If you want to change the IBM service defaults, change the PPFs using $PPF overrides on the VMSES/E system inventory disk \(51D\) to reflect your system configuration\. For information about tailoring the PPF, see [VM/ESA: VMSES/E Introduction and Reference](<DOCNUM/SC24-5444/CCONTENTS>)\.

```
 |          ___ Note _______________________________________________________
           |                                                                |
 |         | If you have updated the 190 or 193 disks you should copy any   |
 |         | new and changed files to the 490 and 493 disks.  This will     |
 |         | avoid accidentally back-leveling modified files.               |
           |                                                                |
           |________________________________________________________________|
```

**4\.** Merge the APPLY disks

Next, you must prepare your system to receive the service from the RSU Tape\. To do this, you must first clear the alternate apply disk for receipt of the service from the RSU Tape\. The merge for *all* components must be performed before continuing to the next task\.

Enter the VMFMRDSK command to merge the alternate apply disk to the intermediate apply disk\. This will clear the the apply disks\. If components share the APPLY disk or directory, the merge only needs to be performed once for these components\. For example, CMS and REXX use the 3A6 as the APPLY\. These two components share these disks, so the following command only needs to be entered with either REXX or CMS as the *compname*\.

<a id="TBLTBLUNIQ27"></a>

```
 | vmfmrdsk esa compname apply (setup
```
