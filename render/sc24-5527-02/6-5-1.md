#### 6.5.1 Add Local Source Update Modifications to Service Inventories

The VVTLCL table is the default table used to track local modification to a product or component. Each time an entry is added to a local AUX file (AUXLCL) a correspond entry should be made in the local version vector table (VVTLCL). This will ensure that all local modifications are identified by VMFAPPLY when applying service and build into the objects when VMFBLD is run. To add a local modification to the version vector table the following VMFSIM LOGMOD function would be run.

this field has the format lcmodid.update-ft. **LCL2222** This is the local tracking number given to this modification. The first two characters of this number must be LC. The remaining characters are the modid, which is used to identify the file type used by VMFBLD. The first character of the modid must be L. The file type that would be processed would be a composite of the 3 character file type abbreviation and the modid from the local tracking number (TXTL2222 in this example). This local tracking number must also be identified in the AUX file containing the source update for this part (the AUX file would have a file type of AUXLCL in this example). **UPDTMOD2** Is the file type of the source update file containing the | changes to DMSNGP for this modification.
