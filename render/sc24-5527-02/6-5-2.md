#### 6\.5\.2 Adding Local Replacement Files to Service Inventories

The VVTLCL table is the default table used to track local modification to a product or component\. If a part of the product or component that is serviced by file replacement, for example, no source update files are shipped, is modified the modification must be identified in the local version vector table \(VVTLCL\)\. This will ensure that all local modifications are identified by VMFAPPLY when applying service and build into objects when VMFBLD is run\. If the modification is not added to the VVTLCL file VMFAPPLY will not be able to identify the change and VMFBLD will not pick\-up the modification when building objects\. To add a local modification \(without source updates\) to the version vector table the following VMFSIM LOGMOD function would be run\.

<a id="TBLTBLUNIQ456"></a>

```
 | vmfsim logmod tblfn vvtlcl e tdata :part dmsabc exc :mod lcl2222
   vmfsim query  tblfn vvtlcl e tdata :part dmsabc exc
   VMFSPC2480I Results for TDATA :PART DMSABC EXC
   :PART DMSABC EXC
      :MOD LCL2222
      :PTF
```

The VMFSIM LOGMOD function added the local modification LCL2222 to the VVTLCL table for the part DMSABC EXC\. This local modification is identified in the version vector table on the :MOD field\. The data on this field has the format *lcmodid*\.

**LCL2222** This is the local tracking number given to this modification\. The first two characters of this number must be LC\. The remaining characters are the *modid*, which is used to identify the file type used by VMFBLD\. The first character of the *modid* must be an L\. The file type that would be processed would be a composite of the 3 character file type abbreviation and the *modid* from the local tracking number \(EXCL2222 in this example\)\. Because there are no source updates for this part NO AUX file would be built containing this local tracking number\. Also the version vector table entry would not identify any source update files\.
