#### 6\.4\.2 Determine What Objects Need to be Built

The Build Status table has a list of objects that have been serviced for the component\. To determine the specific objects that have been serviced and need to be built the VMFSIM QUERY command would be issued against the

<a id="VBLDS"></a>

table searching for objects with a status of SERVICED\. These are the objects that need to be built\.

<a id="TBLTBLUNIQ452"></a>

```
   vmfsim query tblfn srvblds * tdata :stat serviced
   VMFSIP2480I RESULTS FOR
               TDATA :STAT SERVICED
   :BLDLIST HCPMLOAD
      :OBJECT DIRECTXA
      :STAT SERVICED.09/16/92.13:09:59.MAINT
   :BLDLIST HCPMLOAD
      :OBJECT CPEREPXA
      :STAT SERVICED.09/16/92.13:09:59.MAINT
   :BLDLIST HCPMLOAD
      :OBJECT MONWRITE
      :STAT SERVICED.09/16/92.13:09:59.MAINT
   :BLDLIST HCPMLOAD
      :OBJECT OVERRIDE
      :STAT SERVICED.09/16/92.13:09:59.MAINT
   :BLDLIST HCPMLOAD
      :OBJECT HCPCCU
      :STAT SERVICED.09/16/92.13:09:59.MAINT
```

The query returns the following data:

**Field Data Definition**

**:BLDLIST** This field contains the name of the build list that contained the object\.

**:OBJECT** This field contains the name of an object that is contained in the build list\. A build list can contain one or more objects\.

**:STAT** This field contains the status of the object followed by a number of qualifiers that identify the date and time the object was built, and the user ID used to build the object\. Because SERVICED was specified as a search argument only those objects that have new serviced applied will be returned by the query\.
