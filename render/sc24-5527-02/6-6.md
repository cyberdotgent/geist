### 6\.6 Recovering Service Inventories

<a id="VRECS"></a>
<a id="TBLTBLUNIQ457"></a>
<a id="TBLTBLUNIQ458"></a>

```text
   If for some reason it is necessary to recover the service level
   inventories the following procedure should be followed.
   1.  Recover the SRVREQT, SRVRECS and SRVDESCT tables.  The SRVREQT,
               and SYSDESCT system inventory tables are created from the fn
       $PTFPART files using the VMFSIM INIT function.  To recover these
       service inventory files use the VMFSIM INIT function to create these
       tables.  To do this requires creating a list of all $PTFPART files for
       the product or component.
   vmfsetup esa compname
   listfile * $ptfpart * (exec                    The prodid SRVREQT table will be updated to
   vmfsim init prodid * fm file cms exec          reflect all requisite data contained in the
                                                  $PTFPART files processed.
                                                  The prodid SRVDESCT table will be updated
                                                  to reflect all APARs and the descriptions
                                                  associated with them in the $PTFPART files
                                                  processed.
                                                  The prodid SRVRECS table will be updated to
                                                  have a status of RECEIVED for each $PTFPART
                                                  files processed.
 |                                                fm is the file mode of the delta disk for
                                                  the component.
 |     Note:  If you had committed PTFs in the SRVRECS table, (in other
 |     words, a status of COMMITTED) then the status will have to be reset to
 |     COMMITTED after issuing VMFSIM INIT.
   2.  Recover the SRVAPPS and version vector tables.  The SRVAPPS and VVTVM
       system inventory tables are created by the VMFAPPLY command.
       Following is an example of the command to issue to rebuild the SRVAPPS
       and version vector tables.
   vmfsetup esa compname
   listfile ctlfile $ap* * (exec args
   erase reapp $applist a
   cms cmdcall copyfile reapp $applist a (append
 | vmfapply ppf esa compname (exclude fn-exc applist reapp
                                                  This set of commands will create a master
                                                  apply list containing all PTFs for the
                                                  component.
                                                  ctlfile is the file name of the control
                                                  file identified on the :CNTRL. tag in the
                                                  PPF file.
                                                  If any appid VVTVM files exist for the
                                                  component on the apply disks, they must be
                                                  erased or renamed before running VMFAPPLY.
                                                  The prodid SRVAPPS table will be updated to
                                                  have a status of APPLIED or SUPED for each
                                                  PTF processed.
                                                  The prodid VVTVM table will be updated with
                                                  the levels of all parts processed.
                                                  AUXVM files created for all parts in the
                                                  prodid VVTVM table that were updated and
                                                  require AUX files.
 |                                                fn-exc is the file name of your exclude
 |                                                list (if you have one).
   3.  To recover SRVBLDS tables and rebuild objects.  Run VMFBLD to
       re-generate and/or update the SRVBLDS table and rebuild all objects
       serviced.  Follow the steps identified in the build section for the
       product or component being recovered.
```
