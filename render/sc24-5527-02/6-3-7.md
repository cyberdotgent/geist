#### 6\.3\.7 Create an APPLY List from Two

SRVAPPS Tables The SRVAPPS on the first APPLY disk identified in the MDA section of the PPF contains the most current service level of all PTFs applied\. The

<a id="VAPPS"></a>

on subsequent APPLY disk identified in the MDA section identifies previous service levels of the product or component\. This function would mainly be used for the following purposes:

- To validate that all service that was previously applied is applied in the current service level\.
- To create an apply list that contains all PTFs applied to one copy of a product or component that are not applied to a second copy of product or component\.
- To create an apply list that contains all reach\-ahead service that is currently applied to a product or component and not contained on a service refresh tape, for example, Product Service Upgrade \(PSU\)\.

To use this function, enter VMFSIM COMPTBL as follows:

<a id="TBLTBLUNIQ449"></a>

```
   vmfsim comptbl tblfn2 srvapps h tblfn1 srvapps g tdata :ptf (applist new
   ===== * * * TOP OF FILE * * *
   ===== * APPLIST FROM VMFSIM COMPTBL 6VMVMA20 SRVAPPS K 6VMVMA20 SRVAPPS J
   ===== UM18537
   ===== UM18538
   ===== UM18583
   ===== UM18598
   ===== * * * END OF FILE * * *
```

The VMFSIM COMPTBL function will compare the PTF entries in the first

<a id="VAPPS"></a>

table to the PTF entries in the second SRVAPPS table\. Any PTF that is found in the first SRVAPPS table and not in the second SRVAPPS table will be added to the NEW $APPLIST\. The NEW $APPLIST could now be used as input to the VMFAPPLY command to install all PTFs that were applied in the first table and not in the second\. This would make both levels contain the same service level\.
