### FRONT\_1\.2\.1 New Function

Following is a summary of new function for this release:

- ***VMSES/E Enhancements:*** Following is a summary of some of the key enhancements to VMSES/E that affect the way VM/ESA is serviced\.

VMSES/E provides build support for MACLIBs, TXTLIBs, and LOADLIBs\. There are new part handlers invoked by the VMFBLD EXEC to automatically build each of these\. Manual invocation of the VMFMAC EXEC is no longer required to build MACLIBs, TXTLIBs, and LOADLIBs\. Now, each MACLIB, TXTLIB and LOADLIB will have a build list associated with it, containing all the objects that constitute its members\. When any of these objects needs to be built, VMFBLD will invoke the necessary part handler to take appropriate action\.

VMFINFO is a new panel interface to the VMFSIM command\. VMFINFO provides many task\-oriented queries using VMFSIM parameters\. Using VMFINFO, you can select specific query topics, and have VMFINFO invoke the required VMFSIM parameters rather than entering them manually\. The VMFSIM command may still be entered on the command line as in Release 1\.1\. Samples in [Chapter 5, "Using the](5-0.md) [System Level Inventory"](5-0.md) and [Chapter 6, "Using the Service Level](6-0.md) [Inventory"](6-0.md) where VMFINFO can be used instead of VMFSIM are identified\.

ESALCL $PPF is a new override PPF for making local modifications\.

Service for a Product Service Upgrade \(PSU\) is no longer shipped on a Recommended Service Upgrade \(RSU\) tape plus 4 volumes of Refreshed Product Tapes\. All of the service is shipped on the one RSU tape now\.

VMSES/E does not build using AUX files anymore\.

There is no longer an alternate delta disk and a production delta disk\. There is only one delta disk\. This disk contains all files received from a service tape, plus the software inventory files generated by the VMFREC command\.

- ***VMSES/E Saved Segment Support:*** VMSES/E handles the building of saved segments for VM/ESA using the VMFBLD command\.
- ***CP Configurability support:*** CP Configurability support externalizes all of the system definition data from the CP nucleus and makes most of that data dynamically changeable\. You can now dynamically build the system's I/O configuration at IPL time and change device characteristics using commands\. Additionally, you can use new commands to improve system operation, interactively debug the system, exercise greater control over impact printer jobs, and create and purge spool files asynchronously\.
