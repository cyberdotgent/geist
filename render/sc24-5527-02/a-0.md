# A\.0 Appendix A\. Receiving COR Service from ServiceLink

<a id="HDRSEE"></a>

```
 |  ___ Note _______________________________________________________________
   |                                                                        |
 | | Substitute this procedure for the Receive Service procedure in the     |
 | | step for the component you are servicing.                              |
   |                                                                        |
   |________________________________________________________________________|
```

**1\.** Follow procedures in the *ServiceLink User's Guide* to retrieve and decompact the envelope file on your A\-disk\.

**2\.** If the file name of the ServiceLink files are of the format VLST*nnnn* and VPTF*nnnn*, then they are in VMSES format\. Use the following steps to receive the documentation and VM/ESA service\. If the file name is of the format NLST*nnnn* and NPTF*nnnn*, then use the steps in [Appendix B,](b-0.md) ["Receiving Service For Non\-VMSES Envelopes" in topic B\.0](b-0.md) to receive the documentation and service instead\.

**3\.** Receive the service documentation from the documentation envelope VLST*nnnn* SERVLINK\.

**Notes:**

a\. You need to do this operation only once for each envelope file, no matter how many products or components are in each envelope file\.

b\. To create a SERVICE DISKMAP file for the corresponding PTF envelope, issue the following command and substitute VPTF*nnnn* for VLST*nnnn*\.

<a id="TBLTBLUNIQ501"></a>

```
 |                                                nnnn is the last 4 digits of your COR order
 | vmfrec info (env vlstnnnn                      number.
```

VMFREC:

- Loads the COR VMELEDOC file which contains the order information for the envelope\. This file is unique for each envelope\. If there are multiple envelopes to be received, this file should be reviewed prior to receiving the service documentation from the next envelope\.
- Loads the COR DOCUMENT\.
- Loads the product memo files \(*prodid* MEMO\)\. *prodid* is the product ID of the product\(s\) or VM/ESA component\(s\) that are in the envelope\.

**4\.** Read the memo\-to\-users for each product that you plan to service\.

**5\.** Receive the service for VM/ESA from the PTF envelope VPTF*nnnn* SERVLINK\.

<a id="TBLTBLUNIQ502"></a>

```
 |                                                esa is the file name of the base product
 | vmfrec ppf esa compname (env vptfnnnn          parameter file.  If you have a product
 |                                                parameter override file, you should
 |                                                substitute that file name for esa. The file
 |                                                type must be $PPF.

 |                                                compname is the name of the component.
```

VMFREC:

- Maps the envelope file \(verifies that all the necessary files exist\) and creates a SERVICE DISKMAP file\.
- Loads service for the component\.

**6\.** Review the receive message log \($VMFREC $MSGLOG\)\. If necessary, correct any problems before going on\. For information about handling specific receive messages, see *VM/ESA: System Messages and Codes*, or use online HELP\.

<a id="TBLTBLUNIQ503"></a>

```
 |                                                Use the PF10 key to look at all non-status
 | vmfview receive                                messages.
```
