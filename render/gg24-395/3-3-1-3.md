### 3\.3\.1\.3 VM Resource Management

<a id="HDRHAPC103"></a>
<a id="FIGFAPC105"></a>
<a id="EFIG"></a>

```text
   Resource management is an important concept in VM.  Important aspects of
   resource management in VM include the naming of the resources, the
   "visibility" of the resource, and the way VM systems are interconnected.
   Each resource is identified by a resource name.  There are four types of
   resources.  The principle difference between these resources is their
   visibility to clients in the network.  Not all resources can be seen by
   remote clients.
   Factors affecting resource visibility include the type of resource and the
   way in which the VM system is connected to the network.  In terms of
   resource management, VM is connected to the external world through an
   intermediate server.  Intermediate servers include AVS, TSAF, and ISFC.
   They are discussed with more detail in Section "Remote Access Servers."
   AVS       Access across a SNA network.
   TSAF      Connecting VM to VM only, forming TSAF collections.
   ISFC      Interconnecting multiple VM systems forming Communication
             Services (CS) collections.
   Another important difference is whether the resource is identified to CP.
   CP will maintain tables about resources it knows and are located on the
   local system.
   There are four main types of resource (Figure 36):
   GLOBAL    Known and accessible to all users on all interconnected systems.
             Identified to CP.
   LOCAL     Known only to users on the local system.  Only users on the
             local system can access this resource.  Identified to CP.
   PRIVATE   Known only to the virtual machine in which it is located.  Not
             identified to CP.
             To access this resource a user must not only know the resource
             name but must also know the user ID that runs the resource
             manager.  However, the resource is accessible from any
             interconnected system.
   SYSTEM    A mix of the other three.  They are identified to CP and known
             only on the local system, but they can be accessed from other
             systems provided they are directly addressed.  Unlike global
             resources, their name is not propagated through the VM
             collection.
   Global, system, and local resource managers connect to a CP system service
   called *IDENT.  As they connect they specify the name of the resource that
   they are managing.
   Each resource name must be unique within its name space.  As you can see
   from Figure 36, the name space for local and system resource is the system
   on which the resource manager runs.  A global resource's name space spans
   all interconnected systems.
   __________________________________________________________________________

   Figure 36. VM Resource Management
   Global, system, and local resource managers must be logged on and running
   all the time.  If they are not, then any requests to access them will be
   denied.
   Private resource managers do not identify themselves to the *IDENT system
   service, and are therefore not known directly by CP.  They are
   "identified" while executing their PROFILE EXEC, which should include the
   line SET SERVER ON.  This CMS command enables CMS private resource
   processing.
   To identify the private resource names, a special NAMES file,
   $SERVER$ NAMES, is defined as shown below.  This file also identifies the
   resource manager program by name and a list of authorized users.
    __________________________________________________________________________________
   |                                                                                  |
   |  $SERVER$ NAMES    X1  V 255  Trunc=255 Size=8 Line=0 Col=1 Alt=0                |
   | ====>                                                                            |
   |                                                                                  |
   | 00000 * * * Top of File * * *                                                    |
   | 00001 :nick.pres     :list.kris ronaldof brad                                    |
   | 00002                :module.modulep1                                            |
   | 00003 :nick.pres2    :list.vetter pascoa                                         |
   | 00004                :module.modulep2                                            |
   | 00005 :nick.globres  :list.op racfvm operator                                    |
   | 00006                :module.globres                                             |
   | 00007 :nick.resmgr   :list.maint fred catskill creek                             |
   | 00008                :module.globres                                             |
   | 00009 * * * End of File * * *                                                    |
   |                                                                                  |
   |__________________________________________________________________________________|
   Private resource managers do not have to be logged on all the time.
   Incoming requests from requestor virtual machines will identify the
   resource name and the resource manager.  If this user ID is not logged on,
   then CP will autolog it.
   Once autologged, the CMS server environment is started by the SET SERVER
   ON command.  The $SERVER$ NAMES file is searched for the resource name
   and, if the calling user ID is found in the authorization list, the
   resource manager program will be started.
```
