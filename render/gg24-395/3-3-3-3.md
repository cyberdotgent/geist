### 3\.3\.3\.3 TCP/IP and DCE Terminology

<a id="HDRHMIX100"></a>

When reading this document, some terms might be new to you, so it is not unlikely that you could get somewhat confused\. Some terms, such as RPC , are even used in different environments, but are incompatible\. We'll list some terms that we feel could cause confusion\. For more detailed information, see the appropriate section of this document\.

*TCP/IP*: The lower, networking levels of TCP/IP are heavily used by DCE\. So today, the TCP/IP product is a prerequisite to use DCE in OpenEdition VM\. *RPC*: Both DCE and TCP/IP use this term to mean Remote Procedure Call\. RPC allows a program to call a subroutine that will be executed on a remote system\. The implementation by TCP/IP and DCE is incompatible\. So for example, a TCP/IP RPC program cannot call a DCE RPC subroutine\. Another major difference surfaces with *Connection\-less RPC*\. *Connection\-less RPC* uses the unreliable UDP protocol for transportation\. TCP/IP's RPC is then unreliable too, whereas DCE's RPC is reliable by extra logic in RPC\.

RPC should not be confused with REXEC, the TCP/IP feature that allows you to execute commands remotely\.

*Name services*: Both TCP/IP and DCE provide functions\. In TCP/IP it is called "Domain Name System," and allows usage of names instead of internet addresses\. DCE on the other hand allows usage of user\-oriented names for various objects \(such as users, machines and services\) with its "Directory Services\." *Distributed File system*: This is the term DCE uses for "Network File System" \(NFS\)\. TCP/IP and DCE do implement the same model\. NFS should not be confused with TCP/IP's FTP\. FTP is a method to send files; NFS allows you to share the file over a network\.
