## 2\.1\.1 Why Open

<a id="HDRHPRT201"></a>

Today's businesses contain a number of different information technology platforms\. These platforms are often produced by different vendors, conform to differing standards, and run different components of the business' application suite\. As the requirements for information increase, we must link the systems throughout the enterprise into an integrated network\. To be able to interconnect the variety of platforms and existing proprietary systems requires some level of platform commonality\. *Interoperability* means that systems from several vendors can communicate with each other\. Open interoperability means that applications should not be locked into any particular hardware or software platform\. The marketplace does not want proprietary solutions\. For Open Systems to allow interoperability and application portability, systems must be built according to common, industry\-wide standards\. If the application infrastructure conforms to the set of standards, then the control of the environment is in the hands of the business\.

Along with this infrastructure many organizations stated that their employees require access to their information from both inside and outside the enterprise, and no matter what vendor's hardware it resides on\. These requirements suggest the need for new standards to be accepted across the industry\. A representative organization who responded to this need for standards is X/Open\. X/Open, fully described in ["X/Open" in topic 2\.2\.2](2-2-2.md), surveyed its members and in January 1992, published a report entitled *The Open Systems Directive*\. In this report are identified the top five strategic requirements which follow:

1\. Interoperability across heterogeneous systems and networks

2\. An overall architecture for enterprise Open Systems computing

3\. Heterogeneous, networked database access and management

4\. Integrated open and proprietary network management

5\. Open Systems access to data on proprietary mainframe applications

To implement and enhance these user requirements, it is first necessary to refine them into a set of open infrastructure requirements, such as: **Multivendor Interoperability** The basis for this connectivity is the capability to support a variety of networking options across and beyond their enterprise\. **Transparent Access to Data** Information, wherever it resides, must be accessible in a transparent and nondisruptive way\. Applications and user tools must have the ability to transcend vendor and protocol barriers, while ensuring that sensitive information is safe from theft, manipulation, and destruction\. **Remote Application Access** Authorized users, both people and programs, must be able to access applications, wherever they may reside, to complete a task\. **Multivendor Systems Management** Tools and mechanisms are needed to manage all the systems resources\. A complex problem in a homogeneous world, this challenge is significantly more difficult in a multivendor and multiprotocol environment\. **Transaction Processing Across Systems** For the evolving distributed processing environment, users require the ability to do open transaction processing through support of standard communication protocols\. This allows applications to interoperate between platforms, and permits user and application portability\. **Multivendor Security** As the enterprise opens its resources through interoperability to both its own users and those of partners and customers, facilities must be available to protect these assets from both accidental and intentional misuse or destruction\. **Consistent User Interface** For the user to operate productively in this mixed environment, a consistent interface to the varied systems and applications is required\. **View and Print Anywhere** Users need the ability to both display and create printed output through use of a consistent set of view and print capabilities, across the enterprise\. They want to do this with the assurance that what was edited on the workstation will be the same as what is produced elsewhere on a high\-speed \(or other\) printer\. **Application Flexibility** For the application developer, provide a development capability that is consistent across platforms, and supports the flexibility of running the application on a variety of systems, both IBM and others\. **Integrated Application Solutions** Customers are asking for a consistent application for a heterogeneous environment\. This is particularly important, they say, for applications that are an integral part of the business, such as OfficeVison/VM\. **Portability** The ability for people to move from workstation to workstation with minimum effort is required\. Also, the ability to place data and applications anywhere in the network, without concerning the user is an additional requirement of portability\.

Why Open? It is the part of the information infrastructure that allows information technology to be implemented across a multivendor environment\. Open Systems then is a style, a view, a concept of computing that is based on a responsiveness to the growing requirements of computing in the 1990's\.
