## 3\.3\.10 LAN File Services/ESA

<a id="HDRHLFS100"></a>

<a id="TBLTBLUNIQ16"></a>

![PICTURE 77](77.png)

```
 |                 LAN File Services/ESA (LFS/ESA) allows workstation users on
 |                 TCP/IP networks and OS/2 LANs to share, store, retrieve and
 |                 process files stored on VM DASD, thus taking advantage of host
 |                 DASD capacity, speed, and security.  Let's take a closer look at
 |                 the benefits of LFS/ESA, its implementation and some details of
 |                 its major functions.

 |                 LFS/ESA was developed out of the need for customers to more
 |                 easily share their data across their enterprise.  With the
 |                 advent of data being stored not only on workstations but on host
 |                 systems as well, sharing data between these systems was slow,
 |                 cumbersome, and error prone.  As well, sharing data between
 |                 different types of LANs also was difficult.  LFS/ESA addresses
 |                 these problems by allowing OS/2 LANs and TCP/IP networks to
 |                 share data using the LFS/ESA server on VM.
```

Here are some of the benefits of using LFS/ESA:

- Access to host DASD

By storing workstation data on the host, LFS/ESA offers the workstation user a high performance, large capacity repository for their data\. If there are storage constraints on either the LAN server disk or the user's workstation, LFS/ESA will help alleviate this problem\. As well, this data also gets the benefit of host DASD security and stability\.

- Transparent File Sharing

LFS/ESA on VM allows file sharing between users of different file formats, a feature unique to VM\. For instance, a user can choose to store files in LFS/ESA in either CMS or workstation format\. CMS formatted files can be shared between CMS and workstation users within the limitations of the CMS file system\.

LFS/ESA even allows file sharing between users in an OS/2 LAN Server environment and users in a TCP/IP environment\. Files can be shared read/write between these different groups of workstation users\. LFS/ESA provides a lock manager to ensure data integrity\.

All these functions are managed transparently to the end user and without any new code needed on the user's workstation\. Data is converted from CMS to workstation format transparently by LFS/ESA whenever a workstation user accesses a CMS file\. However, a CMS user does not have transparent access to workstation data\.

- Centralized Administration LFS/ESA gives the ability to administer several LANs from a centralized CMS user ID\. Typical LAN administrator tasks would include:

Monitoring DASD capacity

Importing files to LFS/ESA directories

Adding and deleting minidisks for use by LFS/ESA

Backing up and restoring LFS/ESA minidisks

Adding another Front End Processor \(FEP\), user, or LFS Server virtual machine\.

Defining access control for FEPs or users

Optimizing LFS virtual machine performance

As with LANRES, these commands are CMS commands\. This allows the administrator to easily automate repetitive tasks through locally written REXX EXEC or CMS pipeline routine, and centralize the administrative tasks for multiple LANs\.

- Backup and Restore of Workstation Data

The LAN administrator also has an interface to the backup server to allow a centralized backup of user workstation data to S/390 DASD\. The backup and archive facilities of ADSM are discussed in Section ["ADSTAR Distributed Storage Manager" in topic 3\.3\.11](3-3-11.md)\.
