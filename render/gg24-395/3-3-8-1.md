### 3\.3\.8\.1 Host Management Facilities/VM Functions

<a id="HDRHMFF101"></a>

Host Management Facilities/VM offers the following functions:

- Monitor Service Virtual Machines \(SVMs\)

SVM monitoring controls the status of certain SVMs\. If a SVM must be logged on all the time and another SVM found it logged off, HMF autologs the SVM\. HMF also detects the SVM state, such as VM read, CP read, and disabled wait state\. HMF offers an exit for problem resolution and recovery actions\. SVM monitoring can be done at various intervals; for example, monitor user ID VMVTAM every five minutes, Monday\-Friday, from 7AM to 8PM\.

- Start up SVMs

The second SVM control function is used to start up systems, devices, and SVMs at certain times\. It is also possible to specify SVM interdependencies; for example, do not autolog RSCS until GCS is up\. Dynamic control of SVM monitoring is possible using commands\.

- Schedule System Events Scheduling of system activities or events can be automated by the scheduling mechanism of HMF\. Examples of events include CP, CMS, or HMF\-specific commands\. Events can be scheduled to run once or at various intervals\.
- Schedule Personal Events

End users can use HMF to schedule personal events, including reminders, to\-do items, personal autologs, and commands the user is authorized for\.

- Perform Console Automation

The console automation service part of HMF offers similar functions as the Programmable Operator \(PROP\) of VM with some enhancements\. Console automation service can be used to automate message handling at the operator's console\. The functions include message filtering, message logging, automatic message response, and routing messages to NetView\. Routing tables used by the PROP facility can easily be converted to a console automation routing table\.

- Control Authorization for Commands

Control authorization for commands allows you to specify that a certain user can issue privileged commands\. The privileged commands can be HMF, CP/CMS, and locally written commands\. Control can be on a user ID or user ID/node ID level\.

- AID Facility

Dynamic cross\-system Single Console Image Facility \(SCIF\), also known as the AID facility, allows authorized users to become an indirect secondary user ID for another virtual machine\. An AID session can be between virtual machines on the same or different systems\. Together with RSCS, the AID facility shows the console output of disconnected virtual machines across systems in the network from one terminal\.

- Broadcast Commands to Your System

The communication facility of HMF provides the ability to route CP, CMS, or application specific commands to SVMs, resources, applications, and users on the same or different systems\. Systems could be VM, VSE, MVS, or AIX\. The SVMs, resources, applications, or users may each require a different communications method\. HMF routes the commands for you\. There is no need for you to remember the appropriate communications needed to route the commands\. HMF supports IUCV, SMSG, SCIF, and APPC/VM\.

- Display System Status and System Performance Data

RTM/ESA or some other performance monitor can collect performance data\. HMF takes the collected data and determines the status of the system, then displays this status\. The collected data can be from one system or multiple systems and be seen from a single host terminal or workstation\. HMF makes it possible to set thresholds and collection intervals\. Automation EXECs can be used to handle performance problems without intervention\.
