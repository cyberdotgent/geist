### 3\.3\.9\.1 Implementation

<a id="HDRHLAN101"></a>

There are three components to the LANRES implementation\. These can be broadly categorized as the host, the server, and the communication path\.

The host component consists of several virtual machines\. There are separate virtual machines for each of the main LANRES functions:

- LANDISK for disk serving
- LANDPRNT for LAN to host print serving
- LANDSPRT for host to LAN print serving
- LANUSER for administration and data distribution

The multiple virtual machines which provide LANRES subfunctions access their code by linking to a single user ID residing on the host\.

The NetWare operating system consists of NetWare Loadable Modules, or NLMs, that act similar to CMS nucleus extensions\. When an NLM is loaded, it becomes part of the operating system and can be loaded and unloaded without disrupting either the server or clients\. Since each NLM provides a certain function within LANRES, only the NLMs that provide the desired functions can be added to the NetWare server\. No LANRES code needs to be installed on the user workstation for the user to take advantage of its function\. LANRES/VM supports all NetWare clients\.

The communication path defines the different communication protocols that the server can use to communicate with the host; for example, direct PS/2 to host channel attachment, TCP/IP, or SNA LU 6\.2\. The differences and implications of each communication path are covered later in this section\.

Currently, LANRES/VM is a separate program product \(5684\-142\), but with the announcement of LANRES/VM R3, IBM has issued a Statement of Direction that LANRES will become a feature of VM/ESA V2 and MVS/ESA in the future\.
