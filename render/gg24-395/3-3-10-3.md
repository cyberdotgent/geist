### 3\.3\.10\.3 LFS/ESA Host Service Machine

<a id="HDRHLFS103"></a>

The LFS server runs as a disconnected service virtual machine and is designed with several layers of function necessary to manage this environment\.

The first layer is a multitasking base containing a preemptive dispatcher that runs tasks based on their priority\. Although this is similar to CMS multitasking, LFS/ESA has its own implementation of this support\. Other functions in this layer are the console handler, message facility, trace and dump routines, and a job initiation and termination routine\.

The next layer is the request router, which enables the different kinds of communication possible within a LFS/ESA environment\. These include:

- APPC to enable communication between VM/PWSCS \(if being used\) and the host server machines
- IUCV to communicate with TCP/IP and the ADSM service machine
- Common Link Access to Workstation protocol \(CLAW\) to communicate directly over the MMC card to the server

Within the LFS server, there are several communications managers that route communication requests to the correct Protocol Conversion Layer \(PCL\)\. For example, TCP/IP requests are routed to the NFS PCL while requests from an OLS are routed to the SMB PCL\. A PCL processes an incoming request and translates it into a common format known as a Common File Repository \(CFR\) command\. The CFR therefore acts as an interface between the PCLs and the file data stored on the VM host minidisks\. This design makes it possible for LFS/ESA to easily add interfaces to other file systems in the future\.

The LFS/ESA server also provides a general purpose, high performance locking service that ensures the integrity of the files and resources of LFS/ESA\. This is necessary since these resources are being accessed concurrently by multiple users\.

Finally, the LFS/ESA server machine also contains the code that supports the command interface used by the administrator\.
