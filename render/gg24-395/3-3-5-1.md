### 3\.3\.5\.1 RSCS

<a id="HDRHRSC110"></a>

A typical VM end user uses the functions of RSCS to send files, electronic mail, and messages to users on other systems\. SENDFILE, NOTE and TELL are the commands he can use for that\. The protocol used for it is called Network Job Entry \(NJE\)\. Job submission to MVS and VSE batch systems is roughly handled the same way as sending files\. RSCS also handles the printing on 3270\-type printers\. NJE provides a store and forward protocol, which means that all systems do not need a direct link\. NJE is classically supported over S/390 channel\-to\-channel, bisync and VTAM connections\. This way, all the peer systems are interconnected and form the so called NJE network\.

Recently, RSCS started to interoperate by improving it's native TCP/IP connections, so customers with TCP/IP networks no longer need to enhance RSCS with local modifications or exit routines\. The following items are of importance here:

<a id="HDRHRSC111"></a>

*ASCII Plotter/Printer support*: Since 1987, gives RSCS native support for some commonly used ASCII printers and plotters\.

<a id="HDRHRSC112"></a>

*RSCS Data Interchange Manager \(DIM\)*: This feature of RSCS was added in 1992\. It allows exchange of electronic mail between VM \(PROFS, OfficeVision/VM, CMS NOTE\) and SMTP users on the TCP/IP network\. The bridge is transparent, both for the VM users as well as the TCP/IP users\.

VM end users do create their mail as usual, for example with:

`note myfriend at ingate`

The "node ID" \(INGATE\) is defined in RSCS as the DIM link; the "user ID" \(MYFRIEND\) must somehow be translated into an internet address\. This translation can be done by defining them in a nickname file in the DIM service machine, or by including a statement in the mail itself, such as:

`<myfriend>:kris@smtpgate.bel.gie`

DIM gets the note from RSCS, translates the user ID and forwards it to TCP/IP's SMTP service machine\. SMTP then sends the note on the internet\.

The advantages of DIM: SMTP users appear as user ID's on the RSCS network; there is no need to modify mailing procedures \(such as the NOTE EXEC\)\. See ["Simple Mail Transfer Protocol" in topic 3\.3\.3\.2\.4](<#HDRHTCP133>) for more information on SMTP\.

<a id="HDRHRSC113"></a>

*TCP/IP Line drivers*: RSCS V3\.2 adds four new line drivers enabling RSCS to use the TCP/IP network\. The new line drivers use TCP/IP sockets to provide:

- NJE over TCP/IP: provides a connection to another NJE node over the TCP/IP network
- Printing on ASCII printers located in the TCP/IP network
- LPD support: receive data streams for delivery on a RSCS destination or printer
- LPR support: to send data streams to a TCP/IP line printer daemon

Additionally, RSCS offers a socket interface making it much easier for customers to write other TCP/IP line drivers\.

So with the latest RSCS release, the RSCS NJE and the TCP/IP networks become better integrated\.
