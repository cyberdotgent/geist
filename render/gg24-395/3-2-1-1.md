### 3\.2\.1\.1 Why POSIX

<a id="HDRHPSX102"></a>

There are several reasons for including POSIX support in VM/ESA Version 2:

- It will allow applications and data to be moved between VM and other POSIX\-compliant platforms\.
- It will allow applications to execute in a distributed environment by providing the underlying support for DCE in VM/ESA Version 2\. This combination of interoperability and portability of applications lays the foundation for VM/ESA Version 2's support of Open Systems\. See Section ["VM/ESA OpenEdition DCE Feature" in topic 3\.2\.2](3-2-2.md) for details on how OpenEdition VM will be implementing DCE\.
- It will lift the burden off software vendors to write system\-specific code, thus making it cheaper and easier to write code that will run on several different platforms\. This opens up the possibility of many more applications available to be run in the VM environment\.
- It will promote CMS as a peer on a LAN of Open Systems\.

There are several benefits that this support will provide to customers:

- Investment protection

Many customers have significant investments in VM applications and data, with growing investments in UNIX\-based applications\. By having the ability to run applications and store data on VM in a format that can be used by other POSIX\-compliant systems, customers can protect their investment in training and application development\.

- Better growth opportunities

POSIX support on VM/ESA Version 2 will allow large scale implementation of POSIX applications\. A larger choice of software products will also be available too, due to the growing number of POSIX\-compliant applications available\.

- Better productivity

With the large pool of UNIX skills that are available in the work place, users will be able to utilize these skills in the VM environment without a huge learning curve\. But any existing VM skills are not thrown away either; OpenEdition VM remains a VM system and is managed as such\.
