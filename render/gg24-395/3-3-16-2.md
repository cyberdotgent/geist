### 3\.3\.16\.2 Development Tools

Common User Access \(CUA\) architecture and Graphical User Interface \(GUI\) have been around for some time, but as more people move to programmable workstations, their importance is becoming clear, as is the lack of support in that area\. Alongside that is the more recent drive for Open Client/Server solutions, again with little in the way of support tools\. Information technology departments need tools to make such development easier\.

It is useful to define three categories of Client/Server tools that increase user and programmer productivity\.

- Screen Emulation Applications

These applications typically capture 3270 or 5250 data and provide an improved GUI for existing mainframe applications\. The host application is not changed, and in fact, since the application logic is driven by the host, you could say that the GUI is a server in the process\. VisualLift product, described in ["VisualLift for MVS, VM,](3-3-17.md) [and VSE" in topic 3\.3\.17](3-3-17.md) is an example here\.

- Graphic Client/Server Applications

Graphic Client/Server applications provide an intuitive graphical interface, along with transparent access to relational database servers\.

With the inclusion of the VM/ESA Graphical User Interface Facility in VM/ESA, writing graphic applications on VM becomes affordable\. Please refer to ["Native CMS GUI Support" in topic 3\.2\.3](3-2-3.md) for more details\.

- Client/Server Transaction Processing

These applications include full transactional database support\. 2\-phase commits and error recovery, for example, are all managed within the implementation\. In these applications, the mainframe's main purpose is as a database server\.
