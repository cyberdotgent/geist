## 2\.3\.2 Open Blueprint Overview

<a id="HDRHDSS120"></a>

Using the above generic model, IBM developed the Open Blueprint to define a structure for a distributed systems environment that provides the base upon which to build, run, and manage distributed applications\. It incorporates many industry standards and enables IBM to respond to customer requirements with products that:

- Allow seamless connection to different systems
- Run on many hardware and software platforms
- Integrate with products and solutions from both IBM and vendors

Since any strategy in the rapidly changing environment must be flexible and dynamic, the Open Blueprint and the details behind it will evolve as new technologies emerge\.

The Open Blueprint addresses the challenges of the open environment by viewing the system as part of a distributed network and viewing the network as though it were a single system\.

The Open Blueprint serves four major roles:

- It helps customers develop their own architectures and organize products and applications in an open distributed environment\.
- It describes IBM's directions for products and solutions in this environment\.
- It guides developers as they meet customers' needs by supplying products and solutions that include the appropriate functions and can interoperate with other installed products\.
- It provides a framework for the integration of new technologies into a distributed environment\.

The Open Blueprint model has distinct components that allow function to be independent of underlying protocols, platforms, and formats\. For example, an application using Remote Procedure Call \(RPC\) does not need to know details of the network it is using\.

As with the generic model mentioned earlier, the boxes in the Open Blueprint \([Figure 11 in topic 2\.3\.3](11.png)\) do not correspond one\-to\-one to specific products\. Rather, they describe the attributes of the supporting software, provide principles and guidelines, and specify the important boundaries and interfaces needed to design a distributed computing environment\. The functional areas specified in the Open Blueprint are actually implemented by different products, different vendors and different system platforms\. Also, the Open Blueprint does not describe how the implementing software is packaged\.
