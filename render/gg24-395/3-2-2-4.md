### 3\.2\.2\.4 DCE Security Service in VM/ESA

VM/ESA Version 2 can participate in a DCE Cell as DCE Security Client accessing the DCE Security Server on another system in the DCE Cell\.

The DCE Security Server provides DCE applications running on VM access to functions \(authentication, authorization, communication integrity\) provided by DCE security service\.

The VM/ESA Security client components are:

- Authentication Service Utilities
- Access Control List \(ACL\) Utilities
- Login Utility
- Security Service APIs

For more information about authentication and ACL, see Section ["Security](2-4-6.md) [Services" in topic 2\.4\.6](2-4-6.md)\.

The DCE applications can run in three different authentication modes:

- Unauthenticated DCE security does not check the credentials of the user who invokes a DCE application nor does it check the credentials of the DCE application itself\. This means that no user DCE login is necessary prior to running the application\.
- Inherited credentials

The DCE application inherits the credentials of the user who invokes the application\. This means that the user who invokes the application must log in to DCE prior to running the application\.

- Self authenticating

The DCE application uses the Security API to log in and authenticates itself to DCE security\.

The level of security is up to you\. When designing the clients and servers, the distributed application programmer has to consider how much security the interaction between clients and servers will require\. To determine security levels for applications, the programmers need to have a deep understanding of the Client/Server relationships\. Once you have chosen to include security in your RPC, your first RPC to the application server will involve additional overhead while the Security Server handles authentication\. If you decide upon private communication with the server, your RPC runtime libraries must perform encryption and decryption of all or part of the data\. Either way, security causes extra processing\.

The VM DCE Security client support can coexist, but it is currently not integrated, with VM RACF security functions\. Information on user attributes is maintained separately from RACF security services\. Thus, VM/ESA users will login to the DCE network once they have originally logged on to VM\. This DCE network login is separate from their VM log on\.

In VM/ESA a user can identify himself to the cell through two new commands that are implemented by the runtime library:

- dce\_login \(if the user is in the shell\) or
- DCELOGIN \(under the CMS\)
