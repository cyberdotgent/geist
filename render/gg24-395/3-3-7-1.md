### 3\.3\.7\.1 NetView Facilities and Monitors

<a id="HDRHNVW101"></a>

This section is an overview of NetView's basic functions, which include:

- Network Communication Control Facility \(NCCF\) This command facility enables operators to issue commands to the system and network resources they control, and to receive centrally, all the messages and other information from these systems\. The command facility has automation capabilities that permit noninteractive command sequences to be stored and executed as a command list, such as a REXX EXEC, NetView's own command list language, or a high\-level language such as C or PL/I\.

In a VM/ESA environment, the operator uses the VM programmable operator \(PROP\) to communicate with the systems and subsystems under their control\. PROP has an interface with NetView that allows sending messages in both directions\. A NetView operator can even become the PROP logical operator for VM\.

- NetView Graphic Monitor Facility The GMF is the NetView component that provides graphic network management under OS/2\. Information is extracted from the NetView information store \(the resource object data manager in NetView Version 2 Release 3\) and displayed in a GUI view of the network\.

Client workstations using GMF can be customized to observe different aspects as needs arise\. One operator may be looking at MVS resource information, another at LANs\.

- Hardware Monitor The hardware monitor is the NetView component that collects, organizes, and displays error information and traffic statistics\. Particular messages can be filtered, and alerts shown at one NetView system and passed to another NetView system for consolidated review\.
- Session Monitor

This monitors SNA sessions for terminals in any of the connected NetView domains\.

- Status Monitor The status monitor indicates the status of SNA resources within the current NetView domain\. It collects the information automatically from VTAM, and is able to automatically reactivate resources when failure is identified\.

The status monitor also provides review facilities for the NetView activity log\.

- NetView Help Desk

NetView contains ample help facilities, including the tailorable help desk function\. Local procedures for correcting user problems can be stored in NetView for retrieval by a help desk employee\.

- Automation Facilities NetView provides the ability for a computing center to include automated processes in their operations\. The automated activities can be driven by events in the system, or by a timer\.

Some common tasks automated using NetView include Initial Program Load \(IPL\) or Initial Microcode Load \(IML\) of a system, starting or shutting down a subsystem such as CICS, replying to system console messages, or alerting particular operators of abnormal system situations\.

- Open Network Management

Any network and systems management application can exchange data with NetView using either the Communication Network Management Interface \(CNMI\) or a LU 6\.2 session\.

SNA networks are supported, as are TCP/IP and OSI networks, using the IBM products TCP/IP and OSI/Communication Subsystem, respectively\.
