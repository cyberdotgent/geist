### 3\.3\.14\.3 CRR Recovery Server

<a id="HDRHCRR103"></a>

The CRR recovery server has two functions, logging and resynchronization\. The logging function maintains the CRR log minidisks, which are essential for CRR\. During sync point processing the SPM supplies the CRR log manager with data that will be recorded in the CRR logs\. The data recorded in the CRR logs does not contain any user data\. It is simply a log of the participants involved in that sync point\. Maintaining the end\-user data such that a rollback can be performed is the responsibility of the resource manager\.

Two logs are used by the CRR recovery server\. They must be identical and should be on different volumes for maximum security\. The CRR logging function records information on both these logs\. In the event that one should fail, the logging function continues using just one of the logs, until such time as the other is made available again\.

If there is a failure during phase two of the 2\-phase commit synchronization process, the CRR recovery server intervenes and performs a resynchronization process\. Resynchronization involves using the data logged in the CRR logs by the SPM and the resync manager\. The resync manager is also part of the CRR recovery server\. This resync manager will try to communicate with the resource managers and other resync managers for protected conversations\. The resync manager waits until all involved resource managers and other resync managers are available and then tries to resynchronize the transaction\. If the failure is permanent, a provision is available to manually resynchronize the resource managers once the connection is reestablished\.
