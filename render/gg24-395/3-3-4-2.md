### 3\.3\.4\.2 APPN Overview

<a id="HDRHVTM110"></a>

SNA is continually improved to make things easier to use, more secure, and more powerful\. APPN is one of the recent enhancements to IBM's SNA network solution\.

APPN provides an easy to use network with decentralized control, but centralized management\. APPN also allows for arbitrary topologies, continuous operation, connection flexibility, and requires no specialized hardware\.

A network in its simplest form could be just two systems connected by a telephone line\. In SNA terms, this is a connection of two Low Entry Network \(LEN\) end nodes\. There is no exchange of topology or configuration data\. This basic connection is sufficient for an elementary APPC connection\.

When three systems are connected, the center node is obviously an intermediate node that has to have additional functions\. This node represents itself as a LEN that owns all the other nonadjacent nodes hidden behind it\. While the LU on the end node sees the partner LU in the intermediate node, the intermediate node must know where the partner LU is located and has to route the transport traffic accordingly\. The current VM implementation of VTAM and NCP provide these LEN and routing functions\.

The need for additional capabilities for management and maintenance of large networks led to a new architecture: Advanced Peer\-to\-Peer Networking Architecture \(APPN\)\. APPN provides an additional support layer to T2\.1 which enables nonadjacent systems to communicate over a single session; that is, to appear as though they are adjacent\.

In summary, since APPN enables nonadjacent nodes to be aware of the network topology as if they are adjacent, APPC programs may communicate freely between nonadjacent nodes:

- Without the need for any APPC programs to be written on the node in between \(intermediate node\)\.
- Without the additional overhead of application programs running in the intermediate systems\.
- Without the need to configure routing tables on the intermediate nodes\.
