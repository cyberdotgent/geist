### 3\.2\.3\.1 Facelifting Applications

<a id="HDRHGUI120"></a>

Some options are available to provide mouse or GUI support for the existing applications\. We'll list a few of the IBM solutions\. The first two run completely on the workstation\.

<a id="HDRHGUI121"></a>

*Communications Manager Mouse \(CMMouse\)*: CMMouse, packaged as a productivity aid with Communications Manager/2, provides programmable mouse support for 3270 emulated host sessions; it does not change the host screens, but may make using host applications more enjoyable\. By tailoring some control files, the mouse buttons can be used to send any sequence of keystrokes to the host, including PFkeys\. In addition you can easily construct popup menus to appear over host screens\. The popup menu items can either send keystrokes to the host, or display another menu\. The CMMouse actions can be made dependant on the mouse position and host screen contents\. This way the sample CMMouse control files can be used to control many popular VM applications, including OfficeVision and FILELIST\. OS/2 REXX statements can be imbedded in the control files to perform advanced actions\.

<a id="HDRHGUI122"></a>

*VisualLift for MVS, VSE and VM*: With the new VisualLift program product \(5684\-109\) you basically replace the 3270 screens with new workstation panels\. The new panels can contain check boxes, radio buttons, push buttons, and so on\. VisualLift provides an application development environment that must be used to map the 3270 screens onto new workstation panels\. Its runtime environment will analyze the incoming 3270 data stream and display the corresponding workstation panel\. If no matching workstation panel is found, or if the 3270 screen seems changed, a 3270 emulator window will be shown\. VisualLift is described in Section ["VisualLift for MVS, VM, and VSE" in topic 3\.3\.17](3-3-17.md)\.

<a id="HDRHGUI123"></a>

*ISPF Client/Server*: Version 4 of ISPF for MVS allows existing ISPF applications, without change, to be displayed on a workstation in a GUI window\. The control of the windows is done at the workstation, avoiding high network loads found in X Window solutions\. The connection is made over SNA or TCP/IP\.

The three solutions mentioned above have an advantage since the 3270 application itself is not changed at all, and the latter two provide a real workstation look and feel\. The CMS GUI support goes one step further and provides both a Client/Server implementation and API\.
