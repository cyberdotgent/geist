## 3\.4\.2 DCE Compliance

<a id="HDRHFUT102"></a>

With the introduction of OpenEdition VM, IBM has added Distributed

Computing Environment \(DCE\) support for VM/ESA\. IBM is investigating several areas that may be attractive to customers implementing DCE\. Areas of possible exploration:

- Adding the Distributed Time Service\.

The ideal implementation of DTS, would synchronize the VM system time with that of the DCE cell\. Therefore, no matter how you ask for the time of day \(STCK instruction, CP Q T, DCE's utc\_gettimetime\(\), REXX or C Time\(\), and so on\.\) you will get back a cell\-synchronized time\.

- Updating the DCE client code on VM to the DCE 1\.1 level\.

This will give DCE applications access to new API's, such as the general security system API \(GSSAPI\) for letting non\-RPC applications perform DCE\-style security\. It also permits better integration of VM user IDs \(native security identities\) with DCE UUIDs \(DCE specific security identities\)\.

The intention is to make VM/ESA V2 even more attractive to customers that are writing distributed applications\.

**Note:** For more information about DCE, see [Chapter 6, "Distributed](2-4.md) [Computing Environment" in topic 2\.4](2-4.md) and ["VM/ESA OpenEdition DCE Feature"](3-2-2.md) [in topic 3\.2\.2](3-2-2.md)\.
