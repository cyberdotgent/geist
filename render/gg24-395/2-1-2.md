## 2\.1\.2 Open Definition

<a id="HDRHPRT202"></a>

As discussed in Section ["Why Open?,"](2-1-1.md) standards are required that will

allow heterogeneous systems to be truly "Open\." To this end, the Institute of Electrical and Electronics Engineers \(IEEE\) published the following \(IBM adopted\) definition of Open Systems\. This definition is contained in IEEE 1003\.0, a guide to POSIX\-based Open Systems\. \(See [Chapter 4, "Standards and Standards Organizations" in topic 2\.2](2-2.md) for further discussion of POSIX and IEEE\)\.

**"An Open Systems environment supports a comprehensive and consistent set of international Information Technology \(IT\) standards and functional standards profiles that specify interfaces, services, and supporting formats to accomplish interoperability, and portability of Applications, Data and People\."**

For our discussions, the significant terms in this definition should be understood as follows: **Standards** A standard is an agreed\-upon definition of a common set of properties and features exhibited by conformant objects\. Some standards are merely mutual agreements between a few cooperating people\. Some standards \("de jure"\) are rules to which members of a corporation must adhere; others are "de facto" standards, which have evolved through common agreement\. Finally there are National standards and International standards\. **Profiles** Profiles are a collection of predefined standards that characterize a certain environment or process\. These chosen standards may belong to different organizations\. An example of a profile is the Document Application Profiles \(DAP\), to harmonize the Office Document Architecture \(ODA\)\. **Interfaces** An interface is a set of programming functions and routines that provide communication between two programs or between an end user and an application\. Examples of interfaces include Application Program Interface \(API\) and Graphics User Interface \(GUI\)\. **Services** Services perform common tasks for programs or end users\. Examples of services include Print Services, File Services, Database Services, Time Services, and Security Services\. For more information about services, see ["Open Blueprint Examined"](2-3-3.md) [in topic 2\.3\.3](2-3-3.md) and [Chapter 6, "Distributed Computing](2-4.md) [Environment" in topic 2\.4](2-4.md)\. **Formats** A format is a documented data representation\. One example of a format is one used by Network File System \(NFS\) called eXternal Data Representation \(XDR\), a standard developed by Sun Microsystems Inc\.\. This format represents data in a machine\-independent format\. Another example of a format is the Graphics Interchange Format \(GIF\), a format for storing workstation picture bitmaps\. **Interoperability** Interoperability is the ability to interconnect systems from different manufacturers, and have them work together to solve business problems\. Clearly more than just networking, interoperability can address a variety of needs\. Interoperability may be needed to satisfy business requirements for message transmission between systems, or to facilitate the sharing of resources, such as data, between applications running on different hardware and software platforms\. **Portability** Portability refers to the ability to relocate system resources \(such as data and applications\) between processing environments of differing design and architecture\. Most commonly, this need tends to focus on application portability, but is not limited to only that set of Information Technology \(IT\) resources\. People must also be able to be moved from one platform to a new one without the need to acquire new skills\. **Investment Protection** Investments made in the past, or future investments to be made in new applications should be protected from external changes as much as possible\. In other words, changes should be transparent to people, to protect the investments made in people and their skills\.

The definitions from above are used throughout the rest of this publication\.
